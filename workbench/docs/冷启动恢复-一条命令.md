# 冷启动恢复：机器重置后的一条命令

> 起因（2026-11-06）：本机「关机即重置」。此前所有自愈能力都放在
> `_notes/workbench/tools/bootstrap.py` —— 而**机器一重置，`_notes` 整个没了，
> 自愈脚本自己也没了**。这条链在最需要它的那天是断的。本文补上起点。

---

## 0. 先判断你在哪一档

| 现象 | 该做什么 |
|---|---|
| `D:/github/_notes` 还在，只是钩子/工具丢了 | 跑 `bootstrap.py`（见 §1），**不需要冷启动** |
| `D:/github/_notes` 整个没了 | 冷启动（见 §2） |
| 换了机器 / 换了盘符 | 冷启动 + `--workspace E:/projX`（见 §3） |

---

## 1. 真源还在：一条命令自愈

```bash
python D:/github/_notes/workbench/tools/bootstrap.py
```

幂等、无交互：建目录 → 同步工具 → `git init`（若无）→ `.gitignore` → 装 pre-commit 钩子 → 跑自测。
**不删文件、不 commit、不 push。**

体检（只读，全绿 rc=0）：

```bash
python D:/github/_notes/workbench/tools/bootstrap.py --check
python D:/github/_notes/workbench/tools/health_check.py
```

---

## 2. 真源没了：从 GitHub 拉回来

真源仓库是**公开**的，**不需要 token**。在任意目录执行（Windows / Git Bash 通用）：

```bash
python -c "import urllib.request,json,base64;u='https://api.github.com/repos/TrueFurina/github-notes/contents/workbench/tools/cold_start.py';d=json.load(urllib.request.urlopen(urllib.request.Request(u,headers={'User-Agent':'x'})));exec(base64.b64decode(d['content']).decode())"
```

它会：下载 tarball（`codeload`，匿名可读）→ 解包（剥掉顶层目录）→ 落到 `D:/github/_notes` →
跑 `bootstrap.py` → **绑定 `origin`**（否则能自愈却不能推回真源，下次重置又白干）。

预期输出（实测）：

```
[1] 下载真源: https://codeload.github.com/TrueFurina/github-notes/tar.gz/refs/heads/main
    已下载 20,527,359 B
[2] 解包（剥掉顶层 github-notes-main/）
[3] 落位 -> D:\github\_notes
[4] 运行自举: D:\github\_notes\workbench\tools\bootstrap.py
  ✓ 判据自测:   self-test PASS
  ✓ 现场守门: ✓ 通过：单一真源、根目录无漂移文档、暂存区无凭据。可提交。
[5] 远端绑定: 已绑定 origin=https://github.com/TrueFurina/github-notes.git
结论: ✓ 冷启动完成，已就绪
```

也可以先把 `cold_start.py` 另存下来，之后 `python cold_start.py`。

---

## 3. 换机器 / 换盘符

```bash
python cold_start.py --workspace E:/projX
python cold_start.py --workspace E:/projX --notes _kb     # notes 目录换名
python cold_start.py --check                              # 只判断是否需要恢复
```

私有 fork 才需要 token（放进环境变量即可，脚本自动带上）：

```bash
set GITHUB_TOKEN=...        # Windows
export GITHUB_TOKEN=...     # bash
```

---

## 4. 安全边界

- **不使用 git 拉取**：代理下 `github.com` 常 502，`codeload` 走另一条路由更稳。
- **先解到临时目录，成功后才改名落位**：网络中断不会留下半成品 `_notes`。
- 若 `_notes` 存在但不完整 → **改名让位**（`_notes.broken-<pid>`），**不删除**。
- 防路径穿越：解包时逐条校验目标路径必须在临时目录内。
- 全程不写凭据到磁盘。

---

## 5. 恢复后建议立刻做

```bash
python D:/github/_notes/workbench/tools/health_check.py        # 8 项应全绿
python D:/github/_notes/workbench/tools/bootstrap.py --list    # 多项目注册表是否还在
python D:/github/_notes/workbench/tools/session_start.py <ID>  # 领会话命名空间再开工
```

> 注：刚恢复的仓是「tarball 解包 + git init」，**没有提交历史**，所以
> `health_check` 的 H6 会显示「尚无提交（跳过）」——这是正常的，不是故障。
> 首次 `git fetch origin && git reset --hard origin/main` 后即与远端一致。
