## 1. 核查方法（以及一次 oracle 假阳性修正）

初版按固定路径列表逐个 GET `CONTRIBUTING.md` / `.rst` / `docs/...`，
结果 3 个仓库报「未找到政策文件」。**不能把「没找到」当「没有」**——
路径猜错和真的没有是两回事（本轮「先怀疑 oracle」的又一次应验）。

改用 **Git Trees API 递归列全仓**（`?recursive=1`，并检查 `truncated=false`），
正则筛 `contribut|code.?of.?conduct|conduct|governance`：

| 仓库 | 默认分支 | 政策类文件 | truncated |
|---|---|---|---|
| tigerless-labs/agent-memory | main | （无） | false |
| pallets-eco/croniter | main | （无） | false |
| jmespath/jmespath.py | **develop** | （无） | false |
| lemon24/reader | **master** | `CONTRIBUTING.rst`、`docs/contributing.rst` | false |
| getludic/ludic | main | `CONTRIBUTING.md` | false |
| openai/openai-agents-python | main | `CONTRIBUTING.md` | false |

→ 3 个「无」是**真的没有**，不是路径猜错。

**第二次 oracle 假阳性**：关键词扫描把 `openai/openai-agents-python` 标成
「需先问/先开 issue」。回看原句，第 41 行是 *"Open an issue before preparing a
**listing change**"*（集成列表变更），与代码 PR 无关；真正硬条款是第 7 行
*"Pull requests are limited to repository collaborators"*，已由 REJECT 判定捕获。
→ **条款命中必须回读原句确认作用域**，不能只看正则命中。

### 落地到 `scout_targets.py` 时又暴露的三次判据问题（均已加 self-test 锁）

把上述方法固化进工具后，从 14 例扩到 **21 例 self-test**，期间连续发现：

1. **`CONTRIBUTORS.md` 是贡献者名单，不是政策**：`ecmwf/anemoi-utils` 递归 trees
   只命中 `CONTRIBUTORS.md`，含 `contribut` 被误当政策文件 → 从 `NONE` 误判成 `UNKNOWN`。
   修法：抽纯函数 `is_policy_file()` 显式排除 `contributors?.`，T17/T18/T19 锁住。
2. **只取第一个政策文件会漏条款**：`ruyisdk/ruyi` 有 `CONTRIBUTING.md` +
   `CONTRIBUTING.zh.md`，早期固定路径读到含 CLA 字样的文件判 `GATED`，
   改读主文件后变 `UNKNOWN`。修法：**合并所有政策文件整体判定**。
   再回读原文发现真实门槛是 **DCO sign-off**（"The DCO is a declaration that you
   make when you sign-off a commit"），不是 CLA → 补 DCO 判据，T20/T21 锁住。
   最终 `ruyi` 正确归入 `GATED / 需 DCO sign-off`，不再算候选。
3. **openai 的 listing change 需作用域排除**：在判 `GATED` 前剔除含
   "listing change" 的句子，T15/T16 锁住（拒收原句仍判 REJECT、
   纯 listing 条款不误判门槛）。

→ **「发现异常先怀疑 oracle」累计应验七次**（本轮 3 次 + 契约库 5 次中的后续）。
政策文件读取与条款判定都必须有回归锁，不能只靠一次性人工核对。

### ★ 新增可操作教训（比政策文本本身更具体）

1. **政策检查不只看正文，还看提交元数据**：触发这次拒绝的是 git commit 的
   `Co-authored-by: TrueFurina Agent` trailer，不是代码或 PR 描述。
   → 开 PR 前除读政策外，**必须检查提交历史里的 agent 署名 / co-author trailer**；
   在禁 AI 的仓库，仅凭 trailer 就足以被拒。
2. **AI 禁令应在「选靶阶段」就一票否决**，而不是等开了 PR 再做事后合规复核。
   本工具 `scout_targets.py` 的 `AI_BAN` 已把这类仓库判为 `EXCLUDE`；
   `--audit-existing` 只用于存量核查。
3. **合规复核的价值是「提前知道」而非「挽回」**：这次提前 1 天识别出风险，
   但没有可挽回的动作；如实记录结果比事后包装更有用。
4. **对 maintainer 的明确拒绝不得重试**：与「不催 maintainer」一致，
   关闭即结论，不换号、不改措辞重提。
