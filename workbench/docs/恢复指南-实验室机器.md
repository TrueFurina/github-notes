# 实验室机器重置后的恢复指南

本机是学校实验室机器，**关机即重置，`D:\github` 全部清空**。所有原创产物已备份到
`TrueFurina/github-notes` 的 `workbench/` 子目录。新机器 clone 一次即可恢复。

## 1. 备份内容

远端 `github-notes`（main）结构：

| 路径 | 内容 |
|---|---|
| 根级平铺 | 笔记类 md（并发会话维护，勿动） |
| `workbench/docs/` | 本机全部原创 md（审计报告、方法论、三天方案、知识沉淀） |
| `workbench/tools/` | 9 个审计工具 + 48 条修复台账 + 26 项 VERIFY + 测试 |
| `workbench/notes/` | push-notes.py、推送说明、深度复盘等 |
| `workbench/scripts/` | 恢复工作流要用：备份脚本、API 推送脚本 |
| `workbench/probes/` | 原创探针脚本（7 类失效形态静态检测） |
| `workbench/work-repo/` | 实验排课系统（前后端、会议纪要、梳理报告） |

## 2. 恢复步骤（新机器）

```powershell
# ① clone（有 git 时）
git clone https://github.com/TrueFurina/github-notes
cd github-notes

# ② 取回产物
#    workbench/docs、workbench/tools、workbench/notes、workbench/scripts
#    拷回 D:\github\ 对应位置（tools 整目录、md 回根目录）

# ③ 设置 token（见下节）
# ④ 之后跑 workbench/scripts/push_workbench_backup.py 继续增量备份
```

若新机器**没装 git**：直接用 `workbench/scripts/gh_push.py` 或 `push-notes.py`，
它们走 Git Data API（blob→tree→commit→PATCH ref），不需要 git 二进制。
下载脚本本身可用浏览器从 GitHub 网页保存。

## 3. Token 问题（关键）

`GITHUB_TOKEN` 存在 `HKCU\Environment`（用户级注册表），**关机重置会一起消失**。
新机器必须重新设置：

```powershell
# 临时（仅当前窗口）
$env:GITHUB_TOKEN = "ghp_xxx"

# 持久（写注册表，本机备份脚本就是从这里读）
setx GITHUB_TOKEN "ghp_xxx"
```

- scope：需要 `repo`（写公开仓足够）
- 安全：token 不要贴进对话、不要写进脚本、不要 commit

## 4. 继续备份（增量）

本机产出新内容后，跑一次备份脚本，它自动比对远端、只推变更：

```powershell
cd D:\github
python workbench\scripts\push_workbench_backup.py
```

脚本特点：从注册表读 token（不写死）、`force:false`（撞并发安全失败）、
只动 `workbench/`、绝不覆盖根级他人文件。

无一处不符、无一个丢失。
