| 前一轮说法 | 实测结果 | 性质 |

**真实定位**：`SecAutoMind` 是 2026 中国青年科技创新「揭榜挂帅」擂台赛的参赛作品，赛题 XH-202609，安恒信息发榜，参赛单位为闽江大学网络空间安全学院。

这解释了很多之前看不明白的事：

**这些不是"工程习惯差"，是赛事交付规范与开源工程规范的冲突。** 之前的批评（"工作区/交付区不分"）在赛事语境下需要打折——提交材料必须自包含，这是评奖要求。

## 一、页面实际质量：比我预期的高

`index.html` 22,628 字符，是一个完成度相当高的单页作品。实测结构：

```
01 · ABOUT          命题回应：赛题要的，正是我们交付的
02 · ARCHITECTURE   五层解耦架构 · 纵深防御设计
03 · INNOVATION     三大技术创新：我们「新」在哪里
04 · VERIFICATION   实测证据：工程闭环不是纸面功夫
05 · DOWNLOAD       下载部署：三步在本机跑起来
06 · NOTICE         授权与合规声明
```

技术侧有具体数字：127,871 行 Go 代码、143 运行时工具（91 YAML + 52 内置）、18 个场景角色、36/36 测试包全绿、292 个测试文件、端口 18086 实启动 HTTP 200。

### 一个值得单独说的细节

"实测证据"章节里有一段**主动自曝短板**的声明：

> 题目来源声明：基准集分两类 —— 真题 55 题（公开 writeup 来源，每题带 source 与 flag_sha256，命中 19/55 = 34.5%）+ 自产题 85 题（gen_*.py 生成 / 自建靶场 / 自造工件，覆盖率 100%，占 60.7%）。**自产题的高覆盖率只证明工程链路可跑通，不构成真实赛场竞争力证据；引用时请区分两类。**

这段写得好。90% 的参赛作品会把 60.7% 包装成"总覆盖率"，你主动拆开成 34.5% 和 60.7% 并声明后者不构成证据——**这是评委最认的信号**，也是你作为安全从业者最该保留的习惯。

（顺带：这也解释了为什么 `AGI-Distiller` 里有 `honesty_scan.py` 这种脚本。你的"诚实"是工程化的，不是临场表态。）

## 三、一个反直觉的发现：这个页面的访客可能不是"用户"

Traffic 数据显示 14 天 78 次浏览 / 23 个独立访客，我上一轮判断"访客是冲着下载来的"。

但结合"参赛作品"这个背景，更可能的解释是：

- **评委与同期参赛者**在互相查看
- **安恒信息的评审**在核对提交材料
- **同校同学**在围观

这解释了两个之前的矛盾：

1. 为什么 23 个独立访客只带来 64 次下载（人均 2.8 次，像在验证下载链接是否可用，而不是真的要用）
2. 为什么 `SecAutoMind-src` 有 3,532 个文件却 0 星——**评委不会给源码仓库点 Star**

**所以"打通双仓链接"的价值要重新评估**：它不会带来大量 Star，因为访客主体不是开源社区用户。

但仍然值得做，理由变成：

- 评委如果对实现细节感兴趣，现在**无路可走**
- 赛事结束后，这个页面会长期存在，届时访客才是真实的潜在用户
- 成本 5 分钟，没有下行风险

**修正后的判断**：这不是"最高回报的动作"，而是"低成本、低风险、补齐明显缺口"的动作。真正的高回报动作要等赛事结束后重新评估。

## 四、赛事语境下，之前哪些建议要打折

| 之前的建议 | 赛事语境下的调整 |
|---|---|
| "删掉 `deliverables/` 和 `submission/` 副本" | **谨慎**。提交材料需要自包含，删了可能影响复核。建议改为：在 `deliverables/` 加 README 说明"此处为提交快照，开发请看 `py-server/`"，并转 private 或移出主仓 |
| "把大赛仓库归档" | **赛后做**。赛程中动仓库有风险 |
| "fork 清理" | **照做**。与赛事无关，纯收益 |
| "统一仓库命名" | **赛后做**。改名会破坏已提交的材料链接 |
| "发 Release 提振曝光" | **降级**。参赛作品的 Release 是给评委看的，不是给社区看的 |
| 安全处置（微信支付密钥） | **优先级不变，仍是 P0**。与赛事无关 |

**一句话**：赛程中"稳定"比"整洁"重要，赛后"整洁"才开始有价值。

## 五、本轮结论

1. **前一轮把参赛作品误判为商业产品**，导致三条建议（补 og、加 preview.png、当产品包装）无效或不当。已更正。
2. **页面质量高于预期**，尤其"实测证据"章节主动区分真题 34.5% 与自产题 60.7% 并声明后者不构成证据——这个诚实度是加分项，不要改。
3. **补丁已实测可用**：2 处插入、+644 字符、结构完整、浏览器验证通过、4 个链接目标均返回 200。
4. **这个页面的访客主体可能不是开源用户**（评委/同期参赛者），所以"导流到源码仓"的预期收益应下调，但成本极低仍值得做。
5. **赛事期间，稳定性优先于整洁度**。副本、命名、归档类建议推迟到赛后。
