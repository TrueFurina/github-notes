## 二、段错误：根因与修复

### 现象

初版跑全量时，5 个测试文件直接 `Segmentation fault`（退出码 139）：

```
test_apply_move / test_graybox / test_master_data / test_slot_alias / test_warmup
```

### 先排除"是我改坏的"

我改的是 `backend/app/security.py`（认证模块），崩溃的是 CP-SAT 求解器（排课优化），看起来无关。但"看起来无关"不等于"确认无关"。

**对照实验**：从 `61b551e222`（改动前最后一个提交）取回原版 `security.py`，替换后重跑：

| 文件 | 新版 | 旧版 |
|---|---|---|
| `test_apply_move` | 段错误 139 | 段错误 139 |
| `test_warmup` | 段错误 139 | 段错误 139 |
| `test_slot_alias` | 段错误 139 | 段错误 139 |

**行为完全一致 → 既有问题，与我的改动无关。**

### 根因

`ortools==9.15.6755` 在 Python 3.12 上调用 `CpSolver.Solve()` 段错误。

最小复现（与项目代码完全无关）：

```python
from ortools.sat.python import cp_model

m = cp_model.CpModel()
x = m.NewIntVar(0, 10, "x")
m.Add(x >= 5)
m.Maximize(x)
cp_model.CpSolver().Solve(m)      # ← 段错误
```

一个容易误判的点：`import ortools` 和 `from ortools.sat.python import cp_model` **都成功**，只在真正求解时崩溃。**"能导入"绝不等于"能跑"。**

版本对照（Windows amd64 / Python 3.12.6）：

| ortools | 行为 |
|---|---|
| 9.15.6755 | 导入正常，`Solve()` 段错误 |
| 9.11.4210 | 正常求解 |

### 修复

`backend/requirements.txt`：

```diff
- ortools==9.15.6755
+ # 9.15.6755 在 Python 3.12 上调用 CpSolver.Solve() 会段错误，详见 docs/ortools-compat.md
+ ortools==9.11.4210
```

修复后 5 个文件全部恢复：

| 文件 | 修复前 | 修复后 |
|---|---|---|
| `test_apply_move` | 段错误 139 | 10 passed |
| `test_graybox` | 段错误 139 | 8 passed |
| `test_master_data` | 段错误 139 | 17 passed |
| `test_slot_alias` | 段错误 139 | 6 passed, 2 skipped |
| `test_warmup` | 段错误 139 | 3 passed |

已推送：

- `6d2c9d7d4e` — fix(deps): pin ortools to 9.11.4210

## 六、一个值得记的细节

原作者在 `requirements.txt` 里写着：

> 版本为「实际验证可运行」的锁定值

锁定的是 `ortools==9.15.6755`。这句话在作者的环境里是**真的**——问题不在版本本身，在 Python 版本组合。

所以"实测可运行"这类声明，必须连环境一起写才有意义：

```
ortools==9.15.6755   # 作者环境可运行；9.15.6755 + Python 3.12 会段错误
```

否则下一个人照着这份 requirements 装，会得到完全不同的结果——而且表现为段错误，最难排查。

---

## 七、这轮的意义

初版跑 1 个文件就宣称"55 passed"，对一个改动了核心模块的变更来说只覆盖了 2.8%。

全量回归的价值不在于"通过多少"，而在于**把"既有问题"和"新引入问题"分开**。这两者混在一起时，没人敢动代码。

而"跑了全量"和"能区分新旧问题"也是两件事——不做前后对照，段错误依然会被误读成回归。
