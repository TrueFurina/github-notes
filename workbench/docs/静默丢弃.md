## 一、先做检测器，再找更多

R112 的教训是"数据算对了，展示时按固定列表过滤，新成员凭空消失"。

这类形态的共同骨架：

```python
for k in HARDCODED_LIST:      # ← 手工枚举
    if k in data:             # ← 数据侧来自别处
        ...
```

数据侧新增成员 → 它不在枚举里 → 不报错、不显示、不计数。

### 检测器：`tools/check_silent_drop.py`

用 AST 找三件事：
- 字面量字符串序列（`("a","b","c")`）
- `frozenset({...})` 之类的常量
- 循环体里是否用 `in <某个名字>` 做过滤

3 项自检，其中 T2 是**反例**：

```
[PASS] T1 固定列表 + 字典过滤 → 检出
[PASS] T2 遍历数据本身 → 不报
[PASS] T3 frozenset 常量 → 检出
```

**T2 是关键**：`for k in data:` 不可能漏，不该报。没有它，"凡循环即报"也能全过。

第一版扫 `audit-sam` 报 **278 处**——绝大多数是安全的：

```python
for prefix in ('/etc/passwd', '/etc/shadow', 'reg query', ...):   # 危险命令黑名单
```

**黑名单/白名单的枚举本身就是完整意图**，不存在"数据侧更大"。

## 三、真缺陷：热力图会漏掉新分类

`scripts/analysis/_scene8_build.py`：

```python
cat_order  = ["web", "crypto", "misc", "pwn", "reverse"]
diff_order = ["VERY_EASY", "EASY", "MEDIUM", "HARD"]
mat = S["regression"]["by_cat_diff"]
```

热力图按这两行遍历。后果有三条，**同时发生**：

1. 题库新增 `forensics` → 它不出现在热力图里；
2. 新增 `EXPERT` 难度 → 同理；
3. 但最后一格总合计用的是 `reg['total']`（**真实总数**）
   → **行合计 / 列合计与总合计对不上**。

第 3 条最要命：表格自己打自己的脸，而且这种不一致**看起来像计算错误，不像"漏了一类"**。

### 修复：优先顺序 + 动态补全

```python
_CAT_PREF  = ["web", "crypto", "misc", "pwn", "reverse"]
_DIFF_PREF = ["VERY_EASY", "EASY", "MEDIUM", "HARD"]
_cats_seen  = {c for c in mat}
_diffs_seen = {d for row in mat.values() for d in row}
cat_order  = ([c for c in _CAT_PREF  if c in _cats_seen]
              + sorted(_cats_seen  - set(_CAT_PREF)))
diff_order = ([d for d in _DIFF_PREF if d in _diffs_seen]
              + sorted(_diffs_seen - set(_DIFF_PREF)))
```

**保留优先顺序，未知成员追加在后**——不是简单地改成 `sorted(mat)`，
那会让 `reverse` 排到 `pwn` 前面，表格变难读。

行为验证（造含新分类/新难度数据）：

```
cat_order : ['web', 'crypto', 'forensics']
diff_order: ['EASY', 'MEDIUM', 'HARD', 'EXPERT']
矩阵内题目总数: 11 （修复前会漏掉 forensics 的 5 题）
```

### 守卫（4 条）

- 必须是派生，不能是字面量（变异：改回写死 → 红）
- 优先顺序常量必须存在（否则会退化成纯字母序）
- 行为级：新分类/新难度必须被纳入
- 反向自检：派生后单元格总和 == 实际总和

## 五、这轮踩的两个坑

### 坑 1：`ast.comprehension` 没有 `lineno`

```python
"line": node.lineno,   # AttributeError: 'comprehension' object has no attribute 'lineno'
```

修：`getattr(node, "lineno", None) or getattr(it, "lineno", 0)`。

### 坑 2：台账的伪仓库名把路径拼重了

```python
p = ROOT / repo / rel     # __tools__ -> D:\github\__tools__\tools\x.py（不存在）
```

`__tools__` 是"工作区级工具"的伪仓库名，它的 `rel` 直接从 ROOT 起算。

修：`p = (ROOT / rel) if repo.startswith("__") else (ROOT / repo / rel)`。

**这个坑很典型**：台账显示"文件不存在"，但文件明明在——如果不去查路径拼接，
会以为文件被删了。

## 七、三条可复用的

1. **固定列表不只是"写死"，它是"完备性声明"。**
   `cat_order` 写五个分类，等于声明"只有这五类"。
   一旦数据侧更宽，这个声明就变成了谎言——而且是无声的。

2. **不一致比缺失更容易误导。**
   热力图漏掉 `forensics`，症状是"合计对不上"，看起来像算错，不像漏类。
   人会去查计算逻辑，而问题在遍历范围。

3. **阈值精度决定工具能不能用。**
