# 三个数字打架：行 50 / 列 47 / 合计 60

- 日期：2026-11-01（R114）
- 起点：R113 修了热力图漏分类，但只修了「遍历范围」
- 这轮发现：**行列合计本身就是两套口径**

---

## 一、同一张表里的三套算法

`_scene8_build.py` 的热力矩阵，三个合计用了三种算法：

```python
# 行合计
t = sum(row.values())                                    # 该分类的全部难度

# 列合计
sum(mat.get(c, {}).get(d, 0) for c in cat_order)         # 仅已列分类

# 右下角总合计
reg['total']                                             # 真实总数
```

**遍历范围各不相同**：行合计看全量难度、列合计看已列分类、总合计看原始计数。

数据正好是 5 类 × 4 档时，三者恰好相等（47 = 47 = 47）——**缺陷完全不可见**。

---

## 二、造数据，让它显形

给题库加一个 `forensics` 分类（10 题）和 `pwn` 下的 `EXPERT` 难度（3 题）：

| 口径 | 值 |
|---|---:|
| 行合计总和 | **50** |
| 列合计总和 | **47** |
| 真实 total | **60** |

**三个数互相打架，没有一对相等。**

而且能看出具体怎么错的：

- `pwn` 行显示 4（含 EXPERT 的 3 题）
- `HARD` 列显示 6（不含 EXPERT）
- 于是行 4 ≠ 列 6 的分解，但总和上又对不上

**一侧算进了不该算的，另一侧漏掉了该算的。**

---

## 三、这类缺陷最难发现的地方

它有三个"隐身"条件同时成立：

1. **当前数据形态恰好让三数相等** —— 5 类 × 4 档，一个不多一个不少
2. **不报错** —— 表格照常渲染，只是数字对不上
3. **看起来像计算错误** —— 人会去查算法，而问题在**遍历范围**

第 3 点最关键。如果数字明显缺失（比如出现空白），人会怀疑"漏了"；
但如果只是"合计对不上"，第一反应永远是"公式写错了"。

我是**造了假数据**才让它显形的。

## 四、修复：统一到共同格点

```python
_cell = lambda c, d: mat.get(c, {}).get(d, 0)
_grid_total = sum(_cell(c, d) for c in cat_order for d in diff_order)

# 行合计
t = sum(_cell(c, d) for d in diff_order)
# 列合计
sum(_cell(c, d) for c in cat_order)
# 总合计
_grid_total
```

三者现在**只在 `cat_order × diff_order` 这个共同格点上累加**，恒等。

### 但差额不能藏起来

如果矩阵里真的存在格点外的题（分类/难度没进表），现在会显式提示：

```python
_all_cells = sum(v for row in mat.values() for v in row.values())
if _all_cells != _grid_total:
    heat_html_note = (f'⚠️ 矩阵共 {_all_cells} 题，'
                      f'其中 {_all_cells - _grid_total} 题的分类/难度不在表内，'
                      f'未计入行列合计')
```

**统一口径 ≠ 假装没有差额。** 差额要单独说，不能靠"总体相等"掩盖。

### 顺带修色阶

```python
cmax = max((mat.get(c, {}).get(d, 0) for c in cat_order for d in diff_order), default=1) or 1
```

原实现 `default=1` 在全空时会得 0（除零），已补 `or 1`。
色阶上限也只按格点算——用全量会让格点外的题把其他格子压暗，而它们根本没被画出来。

## 八、三条可复用的

1. **"合计"这三个字最容易藏口径分歧。**
   行合计、列合计、总合计看起来是同一件事，实际可能是三套遍历范围。
   凡是表格有"合计/总计/小计"，都该问一句：**它们遍历的是同一个集合吗？**

2. **数据形态恰好整齐时，缺陷是隐形的。**
   5 类 × 4 档、47 题，一切刚好。要发现问题必须**造假数据**——
   这也是为什么"用真实数据跑通"不等于"验证过"。

3. **行为测试证明逻辑，源码测试证明接线。**
   我第三次写"复刻逻辑"的测试然后变异发现抓不到。
   结论不再是"下次注意"，而是：**凡是被测逻辑有多个实现副本的地方，必须加源码断言。**
