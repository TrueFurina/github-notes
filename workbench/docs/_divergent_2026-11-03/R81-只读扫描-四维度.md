## 三、为什么不能在剩下的 `relative_to` 上照抄前几轮的模式

`octop-harness/src/octop_harness/backends/workspace.py:350-353`：

```python
def _local_workspace_path(fragment: str, workspace_dir: Path) -> Path:
    local = (workspace_dir / fragment).resolve()
    local.relative_to(workspace_dir.resolve())   # ← 故意让它抛
    return local
```

这里的 `ValueError` **就是返回值契约**：调用方据此把 `../x`、绝对路径越界映射成 `PermissionError`（AGENTS.md §7 `resolve_path` 表：`../x` → PermissionError）。给它包一层 `except ValueError: pass` 等于**取消路径逃逸防护**，而且是那种"测试全绿、只在恶意输入下才暴露"的改动。

同理，`system_archive.py:404` 与 `workspace_archive.py:159` 的 `rmtree` 若改成 `ignore_errors=True`，恢复流程会在**删不掉文件时继续往下跑**，最终产出宽带污染的数据，且没有任何日志。

**判据（写进下一轮的口径）**：一条 `relative_to`/`rmtree` 只有在「抛异常会让一次**本可成功**的用户操作失败」时才算缺陷；如果抛异常是**安全/一致性契约的一部分**，它就是正确实现。
