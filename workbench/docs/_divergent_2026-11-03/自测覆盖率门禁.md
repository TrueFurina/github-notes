# 自测覆盖率门禁 —— 守所有门禁的存在性

- 日期：2026-11-01（R105）
- 起因：R104 审计 SecAutoMind 时提出"应该把自测覆盖率做成门禁"，本轮把它实现并移植
- 产物：`audit-sam/scripts/check_selftest_coverage.py`、`audit-xihu-git/ctf_agent/scripts/_check_selftest_coverage.py`

---

## 一、为什么这条门禁比别的门禁更值钱

其他门禁守的是**代码对不对**；这条守的是**守卫还在不在**。

一个仓库可以有 60 个门禁脚本，运行全绿。但如果其中一半的关键判据写错了、
或者写对了却没人验证过它会不会失败——那 60 个门禁和 60 行注释没有区别。

**这条门禁让"忘了写测试"和"本来就不需要"变成两件可区分的事。**

---

## 二、设计：三选一，都必须表态

每个 `check_* / audit_* / verify_*` 脚本必须满足其一：

| 档位 | 条件 | 说明 |
|---|---|---|
| **A** | 有 `scripts/<name>_test.py` | 最理想 |
| **B** | 脚本自带 `--self-test` | 同等效力（单文件驱动，适合判据型脚本） |
| **C** | 在 `SELFTEST_EXEMPT` 登记 **+ 写明理由** | 显式豁免，可审计 |

三者都不满足 → 红。

### 为什么不用机器猜"它需不需要测试"

机器判不准。`verify_demo_readiness` 要连真服务器、`check_dual_repo_coherence`
要两个仓库同时在场——这些理由只有人知道。

**让门禁去猜，不如让人来签字。**

豁免理由还有长度下限（< 8 字符判红），防止写成"跳过"两个字了事。

### 反向检查：豁免表不能腐朽

`SELFTEST_EXEMPT` 里如果有已经不存在的脚本名 → 红。

这条防的是另一种漂移：脚本删了、豁免登记留着，表越来越长，
最后变成一份没人看的历史清单。

## 三、SecAutoMind：36 个校验脚本，缺口 0

```
校验脚本 36 个
  A 有 _test.py       27
  B 自带 --self-test  4
  C 显式豁免          5
  D 缺口              0
```

5 个豁免全部写明理由，其中两条值得抄下来：

> `audit_scope_boundary` —「脚本自身声明『初筛、不是门禁、不定罪』；未命中≠不在，结论须人工签字」

> `verify_skill_wiring` —「需要 angr/pwntools 等重型依赖 + 真实 skill 树，CI 里装不齐；定位是本地诊断工具」

**一个脚本能说清自己不是门禁，比它扫出什么更重要。**

已接入 `.github/workflows/ci.yml`，与仓库既有范式一致（`--self-test` 在前、本体在后）。

## 四、xihu：31 个校验脚本，移植后暴露 19 处缺口

xihu 的命名习惯不同（`_audit_*` / `_verify_*` 带下划线前缀），且它的"测试"形态不是
`_test.py`，而是 `tests/` 下引用该脚本。移植时改了两处：

1. `PREFIXES` 加 `_` 前缀族
2. 新增 `_referenced_in_tests()` —— 被 `tests/*.py` 引用也算有守卫

结果：

```
校验脚本 31 个
  A 有 _test.py       12   （含本轮补的 1 个）
  B 自带 --self-test  1
  C 显式豁免          18
  D 缺口              0
```

18 条豁免按性质分三组：

| 组 | 数量 | 例子 |
|---|---:|---|
| 单题一次性复现 | 6 | `verify_hgame_rsa`、`verify_vnctf_flag` |
| 需重型外部环境 | 3 | `_verify_web_batch`（要真实靶场） |
| 汇总/阶段脚本（人工判读） | 5 | `_verify_final`、`_verify_stage3` |
| **TODO 应补自测** | **3** | 见下 |

### 关键：TODO 是诚实的，不是假装已覆盖

其中 3 条在豁免表里写的是 `TODO 应补自测`：

```
_audit_corpus_duplicate_pollution: TODO 应补自测：判据是『重复污染检测』，可用合成语料构造
_verify_failopen:                 TODO 应补自测：fail-open 检测本身是可判定的，应当有变异锁
_verify_numeric_dispatch:         TODO 应补自测
```

**这是这份豁免表和普通"跳过"最大的区别**：它明确标出"我知道这里该补，还没补"。
一份全绿的豁免表反而是可疑的。

（第 4 条 `_verify_presolve_truth` 本轮已经真补上了，见下。）

## 五、实际补一个：`_verify_presolve_truth` 的判读逻辑

这是 R59 审计「14 个 offline_verified vs 93 题里只有 2 题可复现」落差的主要证据来源之一。

它的判读逻辑原来埋在 `main()` 的 for 循环里：

```python
verdict = "✅真值匹配" if match else ("⚠️无真值(已提取)" if no_ground else ...)
```

三目嵌套，无法单独测。**抽成 `classify()` 后四类边界才成为可断言的东西**：

| 类别 | 含义 | 为什么必须分开 |
|---|---|---|
| `MATCH` | 提取到且与真值一致 | 唯一的"可验证解出" |
| `NO_GROUND` | 提取到但题库没真值 | **不能算解出**，只能算"待核验" |
| `EXTRACT_BAD` | 提取到但与真值不符 | 最危险：管线给出了**错答案**，不是解不出 |
| `MISS` | 没提取到 | 需要 LLM 推理或独立攻击链 |

**`NO_GROUND` 与 `MATCH` 合并计数，正是口径虚高的来源**：
"题库没真值所以无法反驳"被算成了"解出来了"。

新增 `tests/test_presolve_truth_classify.py`，6 条：

- 四类各自的边界（4 条）
- 反向自检：四类值必须互不相同（防止"全返回同一值"时断言虚假通过）
- 核心一条：`NO_GROUND` 与 `MATCH` 永不合并

### 变异验证

| 变异体 | 结果 |
|---|---|
| `NO_GROUND` 改成返回 `MATCH`（口径虚高） | 3 failed ✅ |
| `EXTRACT_BAD` 改成返回 `MISS`（掩盖错答案） | 2 failed ✅ |

恢复后 6 passed。

## 七、这一型门禁值得推广的判断

我审过的 12 个仓库里：

| 有自测机制的仓库 | 判据质量 |
|---|---|
| SecAutoMind（63 校验脚本 / 47 自测） | 判据基本可信 |
| comment-distillery（每项检查配 `--self-test`） | 判据基本可信 |
| AGI-Distiller（4 道门禁全带 `--self-test`） | 判据基本可信 |
| **其余 9 个** | **判据要么没有，要么没人验它会不会失败** |

**规律很清楚：有自测覆盖的仓库，我找到的缺陷都在"判据没想到的角落"；
没有自测覆盖的仓库，我找到的缺陷往往是"判据本身错了"。**

前者可以修；后者得先让人知道它在哪——这就是这条门禁的作用。
