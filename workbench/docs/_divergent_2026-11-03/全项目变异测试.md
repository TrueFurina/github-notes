## 一、为什么要做全量变异测试

上一轮的发现值得警惕：

> `test_path_traversal_is_blocked` 有 4 个 payload，删掉防护后只有 1 个失败 → **检出率 25%**

这意味着一组看起来完整的测试，实际只有 1/4 在起作用。

那么其他防护呢？鉴权、限流、文件名净化、口令校验——它们是不是也有同样的问题？

**只跑通过率看不出来。必须逐个删掉防护，看测试会不会红。**

## 三、几个变异体的具体含义

### M1 · 签名校验恒真

```python
# 原文
if not hmac.compare_digest(expected, signature):
    return None

# 变异
if False:  # 永远认为签名正确
    return None
```

后果：任何人自己拼一个 `{"u":"admin","exp":9999999999}` 的 base64，加上任意签名就能当管理员。

**8 个测试失败**——说明伪造令牌、篡改载荷这些场景都有真实覆盖。

### M4 · require_admin 直接放行

```python
async def require_admin(request: Request) -> str:
    return 'admin'  # 不做任何校验
```

后果：所有受保护接口（上传、审批、删教师…）全部对匿名开放。

**14 个测试失败**，覆盖范围最广，因为它影响所有写接口。

### M5 · 上传名不净化

```python
def _safe_upload_name(...):
    return prefix + filename  # 直接拼接
```

后果：上传文件名传 `../../app/main.py` 就能覆盖后端代码。

**11 个测试失败**，含后缀白名单、`../` 逃逸、PDF 误传等场景。

### M6 · 限流恒不触发

```python
wait = 0  # 永不限流
```

后果：`/admin-login` 可无限次爆破。

**5 个测试失败**，包括"轮换源 IP 不能绕过"、"全局桶能抓到 IP 伪造"这些较难的场景。

### 脚本的安全性

- 每个变异体执行前 `shutil.copy2` 备份，`finally` 块中恢复 + 删除备份
- 即使中途异常/超时也会恢复
- 退出码：全部检出返回 0，有存活返回 1（可用于 CI）
- 实测跑完后 `find . -name "*.mutbak"` 为空，源码未改动

### 会被跳过的情况

如果某个锚点没匹配上（比如代码被重构了），脚本报 `SKIP 锚点未匹配`，而不是静默通过。这样重构后能立刻发现。

## 八、建议：把变异测试接进 CI

当前 CI 只跑 pytest。可以考虑加一个手动触发的 workflow：

```yaml
name: Mutation Check
on:
  workflow_dispatch:
  schedule:
    - cron: '0 3 * * 1'   # 每周一凌晨 3 点
jobs:
  mutants:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with: { python-version: '3.12' }
      - run: pip install -r backend/requirements.txt
      - run: cd backend && python tests/mutation_check.py
```

**不建议每次提交都跑**——耗时 1 分钟左右（M3 要跑完整认证套件），且变异测试的价值在于定期体检，不是每次 PR 的必过关卡。

每周一次足够发现"有人把防护删了但测试没跟上"的情况。

## 九、这轮的方法总结

之前几轮的教训是"验证动作做了，但验证的不是那件事"。

这轮把那个教训变成了**工具**：

| 阶段 | 做法 | 局限 |
|---|---|---|
| 1. 跑测试 | `pytest` 全绿 | 不知道测试有没有效 |
| 2. 读 skip 原因 | `-rs` 展开 | 只解决"漏跑" |
| 3. **变异测试** | 删防护看是否变红 | 能证明测试有效性 |
| 4. **固化为脚本** | 可重复、可进 CI | 长期防退化 |

第 3 步是这轮新增的能力，第 4 步让它可以被持续使用。

**从这个角度说，这轮产出的不是"又一个报告"，而是一个能在以后每次重构时回答"我的测试还管用吗"的工具。**
