## 一、结论摘要

**这是一份诚实度和工程细节都不错的复现包，但有一个贯穿性问题：优化目标与评价指标用了两套系数。**

| 维度 | 结论 |

| 文档诚实度 | ★★★★★ 主动交代 CP-SAT 多线程导致的不可复现漂移及修复；因标定文档缺失而「不指向一个不存在的文件」 |
| 数据自洽性 | ★★★★★ 25 个结果 CSV **零硬矛盾**（成本恒等式、满足率恒等式、服务率恒等式全部成立） |

## 二、核心发现：ALNS 优化目标与评价指标口径不一致

### 现象（从结果 CSV 直接读出，不需要矩阵）

| 单量 | 完整版总成本 | no_alns 总成本 | 差值 |
|---|---|---|---|
| 120 | 7157.30 | **7095.47** | 完整版**贵 61.83 元（+0.87%）** |
| 240 | 13533.20 | **13525.04** | 完整版**贵 8.16 元（+0.06%）** |
| 360 | **19506.53** | 19592.40 | 完整版省 85.87 |
| 480 | **24515.99** | 25074.63 | 完整版省 558.64 |
| 600 | **29189.15** | 30266.70 | 完整版省 1077.55 |

即：**ALNS 的收益随规模增大而显现，但小规模下是负收益。**

### 根因

`code/solve_full_v5.py`：

```python
# 第 228 行：ALNS 内部目标，超窗权重 alpha = 10.0
def alns_assign(..., iter_max=500, alpha=10.0, ...):
    目标 = alpha*总超窗 + 总里程 + fix_w*路线数

# 第 594 行：最终计分，延迟惩罚 PENALTY = 2.0 元/min
late_penalty = sum((t - due) * PENALTY for ... if not ok)
```

**ALNS 优化时把「晚到 1 分钟」当作 10 元，最终只按 2 元扣钱——相差 5 倍。**

后果链条（120 单实测）：

| | 时间窗满足率 | 骑手里程 | 运营成本 | 延迟惩罚 | 含罚总成本 |
|---|---|---|---|---|---|
| 完整版 | **54.2%** ↓ | **842.68** ↓ | **6178.30** ↓ | 979.00 ↑ | 7157.30 ↑ |
| no_alns | 62.5% ↑ | 865.50 ↑ | 6182.86 ↑ | **912.61** ↓ | **7095.47** ↓ |

ALNS **确实**成功降低了里程和运营成本（842.68 < 865.50，6178.30 < 6182.86），但它用「超窗 10 元/分」的标准主动牺牲了过多准时性——满足率从 62.5% 掉到 54.2%，惩罚反超，最终总成本更差。

**这是一个"局部目标正确、全局目标错误"的经典形态。**

### 文档缺口

README 详细说明了 `PENALTY`（2.0）和 `FIX_W`（实验取 50），但 **`alpha=10.0` 的取值依据在任何文档里都找不到**——`docs/` 下只有 `数据字段字典.md`。这使得它更像遗留硬编码，而非有意设计。

### 修复（不动历史结果）

论文表 6-4~6-8 引用的 `results/*_v5_*` 全部对标 `alpha=10`，改默认值会让既有数字无法复现。因此：

- **默认行为保持不变**（10.0），历史结果可复现；
- 新增 `MARL_ALNS_ALPHA` 环境变量，显式设置时口径对齐（`MARL_ALNS_ALPHA=2`）；
- 非法值 fail-closed（非数字 / ≤0 直接 `SystemExit`，不静默回退）。

实测：默认 10.0 ✅ / `"2"`→2.0 ✅ / `" 2.5 "`→2.5 ✅ / `"abc"`/`"0"`/`"-3"` 全部正确拒绝。

## 三、Quick Start 第一步即失败

README §3 的顺序是：

```bash
pip install -r requirements.txt
# ① 订单已随仓库提供，可直接使用
# ② python code/solve_full_v5.py 600 cdc ...
```

实测第二条命令：

```
FileNotFoundError: ...\data\matrices\OD道路距离_米.npy
```

矩阵约 3.5 GB，README §4 确实写了"不随仓库分发"——**但 §3 的 Quick Start 完全没有提示这个前提**，读者按顺序执行必然在第二步撞墙。

**另有一处路径不一致**：`solve_full_v5.py` 找 `data/matrices/...npy`，`solve_full_v4.py` 找 `data/...npy`。两个版本对矩阵位置的预期不同。

**修复**：在 Quick Start 最前面加「⓪ 前置」，写明必须自备矩阵、并给出"只想核对数字就去看 results/"的替代路径。

## 四、零测试、零 CI

`find . -name "test_*.py"` → 空；`.github/workflows/` → 不存在。

对一个**论文复现包**来说这是最大的结构性风险：`results/` 的 100 个 CSV 就是论文表格的出处，但没有任何机制能在它们被改坏时报警。

**新增** `code/check_results_consistency.py` + `tests/test_results_consistency.py`（6 条），把可机验的层全部钉住：

| 判据 | 内容 |
|---|---|
| C1 | 含罚总成本 == 运营成本 + 延迟惩罚 |
| C2 | 时间窗满足率 == (已服务 − 延迟) / 订单量 |
| C3 | 订单服务率 == 已服务 / 订单量 |
| C4 | 文件名里的「N单」== 表内订单量 |
| C5 | 完整版成本 ≤ 各消融变体（**WARN**，因 120/240 档不成立） |

**实测结果**：25 个 full CSV，**FAIL 0 / WARN 2**（正是上文那两档）。

**变异验证**（注入篡改后）：

| 注入 | 检出 |
|---|---|
| 改「含罚总成本」 | C1 ✅（并连锁触发 C5） |
| 改「时间窗满足率」 | C2 ✅ |
| 改「订单量」 | C4 + C2 + C3 ✅ |
| 取消 C1 判据（M1） | 测试红 ✅ |
| 取消 C5 告警（M2） | 测试红 ✅ |

## 五、值得肯定

1. **README 主动记录失败与修复**：「核验发现 `solve_full_v5.py` 中 CP-SAT 求解器默认多线程且未固定随机种子，导致含 TEN 的实验组存在不可复现漂移；已修复为 `num_search_workers=1` + `random_seed=SEED` 并双重验证后重算」——这是**复现包里最有价值的一段话**。
2. **拒绝指向不存在的文件**：HEAD 提交就是 `docs(readme): stop pointing at a calibration doc that isn't in the repo`，§6 明写「标定依据文档尚未入库，这里不指向一个不存在的文件」。
3. **口径差别的显式警告**：「若以『直线距离×1.35』回退口径运行，数值将与论文不同」——提前堵住"跑出来不一样"的疑问。
4. **数据自洽性极好**：25 个结果文件在三条恒等式上零矛盾，说明生成流程是可信的。
