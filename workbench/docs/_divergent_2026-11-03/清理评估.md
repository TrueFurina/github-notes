## 二、最大的可回收项：`scan_out` 的 19 个解包目录

`github-audit/scan_out/` 是早期批量下载的缓存，**18 个仓库每个都有两份**：

```
AI-Arena/            ← 解包目录
AI-Arena.tar.gz      ← 原始归档
```

我逐对验证过：**19 个解包目录的内容 100% 包含在对应 tarball 里**。
→ 338 MB 可以删，tarball 留着就能重建。

（验证方式是逐文件比对相对路径集合，不是"看起来像"。）

---

## 三、最像缓存的那个，反而不能删

`py312/` 占 **751 MB**，里面只有两项：

```
py312/
├── pkg/          751 MB
└── py312.zip      14.5 MB    ← 看起来是"解压后的缓存"
```

第一眼判断：**zip 是原始归档，pkg 是解包结果，删 pkg 能省 751 MB。**

实际验证：

```
pkg/ 下 21,169 个文件
其中 19,840 个不在 py312.zip 里
```

**那 19,840 个是后来 `pip install` 进去的 site-packages**
（`isympy.py`、`jsonpatch.py`、各种 `.pyd`）。

`py312.zip` 只是 nuget 的 Python 原始包；`pkg/` 是一个**装过依赖的运行时**。

> 删它会丢掉一个装好的 Python 环境，不是"删缓存"。

这条差点被我误判——直到我做了逐文件比对。

## 四、这一轮的两次判据错误

### 错误 1：扫描深度写浅了一层

第一版 `assess_nested(max_depth=2)` 返回 **0 条**。

原因：`scan_out` 相对 `ROOT` 是第 2 层，`<repo>/` 是第 3 层。
`max_depth=2` 走到 `scan_out` 就停了，从未枚举到解包目录。

结果：报告显示"可重建 4 MB（0%）"——**把 338 MB 的可回收空间算成了零。**

### 错误 2：报告漏了一整个分类

修好扫描后，`assess_nested()` 返回 19 项，但报告里还是不显示。

原因：`report()` 里的 `order` 列表手工写死了 5 个类别，
我新加的 `"可重建(同级归档)"` 不在里面，于是被静默丢弃。

```python
order = ["必须留", "可重建(git)", "可重建(归档)", "可重建(内部归档)", "需人工判断"]
#                                                        ↑ 少了 "可重建(同级归档)"
```

**这是"静默丢弃"的典型**：数据算对了，展示时按固定列表过滤，新类别直接消失，没有任何提示。

修法是把它加进列表——但更该做的是**让 report 检查"有没有 category 没被 order 覆盖"**。

## 五、交付：`tools/cleanup_assess.py`（只评估，不删）

| 判据 | 内容 |
|---|---|
| **R1** | 有同源归档，且目录内容**全部**包含在归档里 → 可重建 |
| **R2** | git 仓库且工作区干净 → 可重建 |
| **R3** | 未提交改动 / 唯一副本 / REQUIRED 名单 / 装过依赖 → 必须留 |
| **R4** | 其余 → 需人工判断 |

**这个工具不删任何文件，退出码恒为 0。** 它是评估工具，不是门禁——
不该阻止任何操作。

自检 2 项：

```
[PASS] T1 完整归档 → 判定可重建
[PASS] T2 变异：归档缺文件 → 判不完整
```

T2 是关键：没有它，"凡有归档即判可重建"能全过。

## 六、为什么我没有删

技术上那 346 MB 可以删。但我没删，理由三条：

1. **可重建 ≠ 重建成本为零。** tarball 留着要占 208 MB，删解包目录只省 338 MB；
   重建要解包时间，且上游可能已变更。
2. **删除不可逆，而这是用户的机器。** 我的角色是评估，不是执行。
3. **`scan_out` 是 R111 说的"只读证据"**——它记录着某个时间点的仓库状态。
   虽然能从 tarball 重建，但"它现在就在那儿"这个事实本身有价值。

**把账算清楚，把决定权留下。**

## 八、三条可复用的

1. **"看起来是缓存"和"是缓存"差 19,840 个文件。**
   `py312/` 有一份 zip、一个解包目录，形态和 `scan_out` 一模一样。
   唯一的区别要靠逐文件比对才能看出来。

2. **固定列表过滤会静默吃数据。**
   `order` 列表少一个类别，那个类别的 19 项就凭空消失了，没有任何报错。
   凡是有"白名单/固定分类"的地方，都该反向检查"有没有未覆盖的项"。

3. **评估工具不该有牙。**
   退出码恒 0、不删任何文件——它的产出是判断依据，不是行动。
   有牙的工具会让人不敢跑。
