## 一、结论摘要

**这是我在这 12 轮里见到的、自我验证体系最完整的一个仓库。**

它有 63 个 `check_* / audit_* / verify_*` 脚本，其中 47 个带自测。这个数字本身就说明作者懂"判据必须能被变异打穿"。

| 维度 | 结论 |
|---|---|
| 校验脚本数量 | ★★★★★ 63 个，覆盖供应链/SBOM/密钥/行尾/产物数字/题库口径 |
| 自测覆盖率 | ★★★★★ 47/47 在补齐 git 环境后**全部通过** |
| fail-closed 设计 | ★★★★★ 3 个脚本在非 git 目录下明确拒跑而非放行 |
| **快照类判据** | ★★☆☆☆ 有硬编码快照，此前**无过期告警** |

**结论：这个仓库的验证机制是可信的。我找到的是它的边缘——快照类判据缺少"过期"这一态。**

## 二、审计方法：先验它的判据，再验它的代码

对这个仓库，逐个读代码是最低效的进路——73 MB 读不完。所以换了个顺序：

1. 用 `tools/audit_probe.py` 做一次扫描（535 处，**噪声太大**，见第四节）
2. 转而检验**它自己的校验脚本**：47 个自测逐个跑
3. 找出"零自测"的脚本，判断它们是不是真的不需要

第 3 步是关键——**一个仓库的自测覆盖率，比它有多少 bug 更能说明它的可信度。**

## 三、核心发现：快照判据缺少「过期」态

### D1. `audit_static_miss.py` 里有一份写死的 19 题清单

```python
hit = {'base64_triple_real','breizhctf2022_rsa','caesar_shift19_real',
       'cyberconverge2025_layers','ehaxctf2025_morse', ... }   # 19 题，硬编码
```

这份清单是 2026-10-20 的**快照**，用来界定"哪些题已知可解（HIT）"，从而算出"含可解信号的 MISS 题"。

**问题**：题库 `real_benchmark.json` 现在是 **55 题**，而清单仍是 19 题的口径。

**实测后果**：原实现跑出来一切正常，看不出任何异常——

```
含可解信号的 MISS 题: 2
```

而实际上，那 36 道新增题**从未进入过 HIT/MISS 的划分**，它们被默认归入 MISS。这个数字是失真的，但**没有任何机制报警**。

**这正是我在前几轮反复总结的 S2「空跑即通过」的变体**：
`快照 ≠ 现在` 这个事实，不会体现在任何输出里。

### D2. 修复：给快照加两条自检

```python
SNAPSHOT_TAKEN_AT = "2026-10-20"
SNAPSHOT_POOL_SIZE = 19

# A. 清单里每个题名都必须仍存在于题库（改名/删除会被发现）
_gone = sorted(k for k in hit if k not in ps)
if _gone:
    print(f"[FAIL] 快照清单里 {len(_gone)} 题已不在题库: {_gone}")
    raise SystemExit(1)

# B. 题库规模与快照不一致 → 告警（不是失败，但必须可见）
if len(ps) != SNAPSHOT_POOL_SIZE:
    print(f"[WARN] 题库现有 {len(ps)} 题，快照时是 {SNAPSHOT_POOL_SIZE} 题（{SNAPSHOT_TAKEN_AT}）")
```

**A 用 FAIL、B 用 WARN 是刻意的**：
- 题名消失 = 判据已经错了，必须红
- 题库变大 = 判据**可能**还成立，但口径变了，必须让人看见

修复后立刻生效：

```
[WARN] 题库现有 55 题，快照时是 19 题（2026-10-20）。
       MISS 集合按当前题库计算，但 hit 清单仍是旧的——结论只对旧口径成立。
```

**这个不一致在此之前完全不可见。**

### D3. 顺带发现的 5 个「零自测」脚本

47 个校验脚本里，有 9 个没有独立 `_test.py`；其中 4 个自带 `--self-test`，
**真正两种都没有的是 5 个**：

| 脚本 | 我的判断 |
|---|---|
| `audit_asset_metadata` | 元数据统计，非判据 |
| `audit_scope_boundary` | **明确自称"初筛，不是门禁，不定罪"** —— 定位诚实，不需要 |
| `audit_static_miss` | **确实需要** —— 已补（见下） |
| `check_dual_repo_coherence` | 跨仓一致性，需 git 双仓环境 |
| `verify_skill_wiring` | skill 接线检查 |

`audit_scope_boundary` 那句"**未命中 ≠ 不在**（#188），结论须人工签字"值得单独抄下来——
**它比很多门禁脚本都更清楚自己能力的边界。**

## 四、一次判断修正：探针在这个仓库上不好用

探针扫出 **535 处**可疑点。前几轮它在 1–30 处的仓库上很准，这里彻底失效：

| 判据 | 命中 | 实际问题 |
|---|---:|---|
| S1 静默降级 | 438 | 大量是 CLI 脚本的合理 `except: pass` |
| S2 空跑即通过 | 46 | 多数是 `check_*` 脚本的**正确**判定（`problems` 非空即失败） |
| S3 守卫空转 | 10 | 全部是**带条件的** `skipTest`（题库缺、tesseract 缺），不是永久跳过 |
| S7 边界缺口 | 41 | 包含 CLI 工具的 `read()` |

**判断修正**：静态探针适合 1k–20k 行的中小仓库做初筛；
**在 73MB / 2000 文件规模的仓库上，它给出的量级信息没有意义。**

对这个仓库有效的做法是**验它自己的判据**，而不是用一个外部探针去猜。

这条要写进工具文档：探针的有效范围有上限，超了就该换方法。

## 五、我在这轮犯的错（三次，都是同一类）

补 `audit_static_miss_test.py` 时连错三次，三次都是**测试自身失效**：

| # | 错误 | 性质 |
|---|---|---|
| 1 | 夹具里所有题都在 `hit` 里 → `lens` 为空 → `min()` 崩溃 | 夹具不完整 |
| 2 | 变异锚点写 `'vigenere_known_key'}`，实际是 `,'vigenere_known_key'}` → `replace` **静默不生效** | 变异没生效 |
| 3 | `_run()` 固定跑 `SCRIPT`（原文件），而变异改的是临时副本 → **测了没变异的代码** | 空转 |

第 3 条最典型：**变异必须作用在真正被执行的那份代码上。**

这和我在 R97 批评 DevRadar 那组测试是**完全同一个错误**——
"只测算法等价复刻、绕开调用链"。我在写这个测试的时候，又在犯它。

修好后的 4 条用例：

```
[PASS] T1 基线（清单与题库对齐）→ 不红
[PASS] T2 变异：删除题库题 → 自检红
[PASS] T3 变异：清单含幽灵题名 → 自检红
[PASS] T4 题库规模变化 → 有 WARN
```

**T1 与 T2/T3 是配对的**：只有 T2/T3 的话，把自检写成"永远红"也能全过；
只有 T1 的话，把自检写成"永远绿"也能全过。

## 八、三条建议

1. **把这个仓库的"自测覆盖率"做成门禁**。47/63 有自测，剩下 16 个里 5 个两种都没有。
   建议加一条 `check_selftest_coverage.py`：每个 `check_*/audit_*/verify_*` 必须
   要么有 `_test.py`、要么有 `--self-test`、要么在显式白名单里注明"非判据"。
   这比再写一个新 gate 更有价值——**它守的是所有 gate 的存在性**。

2. **给所有快照类数据加 `SNAPSHOT_TAKEN_AT`**。这次只修了 `audit_static_miss`，
   但"硬编码的题单/数字/名单"很可能还有别处。建议全局 grep 类似的集合字面量。

3. **`audit_scope_boundary.py` 的免责声明值得推广**。它写"未命中 ≠ 不在，结论须人工签字"——
   一个初筛脚本能把自己的能力边界写清楚，比它扫出什么更重要。
