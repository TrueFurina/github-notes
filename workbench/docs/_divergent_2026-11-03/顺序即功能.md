# 顺序即功能：hex 被 base64 抢先解码

- 日期：2026-11-01（R118）

## 三、根因：hex 是 base64 的真子集

```python
# 原顺序
# Base64
padded = text + "=" * ((4 - len(text) % 4) % 4)
result = base64.b64decode(padded).decode("utf-8", errors="replace")
if result and all(c.isprintable() or c in "\n\r\t" for c in result):
    return result            # ← 提前 return
# Base32
# Base16 (hex)
```

`"666c61677b6865787d"` 长 18，`18 % 4 = 2`，补两个 `=` 后是合法 base64。
解出来是 `뮜�^�������`——**其中有字符满足 `isprintable()`**，于是通过检查、提前 return。

**永远走不到 Base16 分支。**

而 hex 的字符集 `0-9a-fA-F` 完完全全是 base64 字符表 `A-Za-z0-9+/=` 的子集——
**这个误判是结构性的，不是偶然**。

---

## 四、修复：按特异性排序

```python
def _try_decode(text):
    """按**特异性从高到低**尝试：Base16(hex) → Base32 → Base64。

    ⚠️ 顺序是功能性的，不是随意的。
    """
    # Base16：全 hex 字符 + 偶数长度（最严格）
    # Base32：大写字母表 + 长度约束
    # Base64：最宽松
```

判定条件越严格的越先试。修完后：

| 输入 | 修复前 | 修复后 |
|---|---|---|
| `666c61677b6865787d` | `'뮜�^...'` | `'flag{hex}'` ✅ |
| base64 | `'flag{hello}'` | `'flag{hello}'` ✅ |
| base32 | `'flag{b32}'` | `'flag{b32}'` ✅ |

## 五、守卫：11 条，两层

### 源码层（2 条）

断言 Base16 分支的**代码位置**在 Base64 之前。

**第一版踩了个坑**：我用 `code.find("# Base16")` 定位，但 `_strip_comments`
会把注释一起剥掉——`-1`，测试直接失败。

改用代码特征定位：

```python
markers = {"16": "bytes.fromhex", "32": "b32decode", "64": "b64decode"}
```

（`bytes.fromhex` 而不是 `b16decode`——这两份实现用的是 `fromhex`。）
这也验证了 R117 的教训：**断言要找代码特征，不是找注释痕迹。**

### 行为层（3 条）

- hex 必须解对
- base64/base32 不能被改坏（反向自检）
- adapter 侧同样

### 跨区一致（5 条参数化）

同一个输入，`skills/` 与 `tools/` 两条链路必须给同一答案。
它们服务不同入口，一旦漂移，同一个输入在两条路径上结果不同。

### 能力边界（1 条）

**把"agents 版更强"这件事写成断言**——不是要求补齐，而是防止有人以为三者等价：

```python
assert rich(two_layer) == "flag{nested}"          # agents 版能解多层
assert "flag{nested}" not in _try_decode(two_layer)  # 单层版解不到底
```

## 八、三条可复用的

1. **顺序是功能，不是排版。**
   `try A; try B; try C` 看着像并列，实际是**优先级**。
   当 A 的条件比 B 宽松时，B 永远不会被执行——而且不报错。

2. **注释里的"替代有 bug 的 X"要当真。**
   `crypto_toolkit` 那句注释是准确的：`base64_multilayer` 确实有 bug。
   但**它只修了一半**（补了循环和 ROT13，没发现 hex 误判）——
   于是 bug 在两个地方活了下来。

3. **"功能更强"和"功能正确"是两件事。**
   agents 版加了循环、加了 ROT13，看起来更完备；
   但 base16 那条分支的 bug 它原样继承了。**扩展一个错误的实现，错误会一起扩展。**
