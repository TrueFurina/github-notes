## 2. 四张清单

### A. 装了但没声明（游离依赖）
**生产侧：无。**
`pip freeze` 146 个包里，130 个不在主清单里，但它们**全部是 8 条声明的传递依赖**，
或 pip/pytest 工具链。用 `importlib.metadata.requires` 求闭包：8 条声明带出 **30 个分发**，
覆盖了 `app/` 用到的全部第三方 import。

⇒ 这不是"游离依赖"，是正常的传递依赖。**不要把它们加进 requirements.txt** ——
加进去等于把传递依赖钉死，反而制造升级冲突。

### B. 声明了但没装（空头支票）
**主清单：无。** 8 条全部装上了。
**dev 清单：无**（pytest 9.2.0、ruff 0.17.3 都在，只是版本比声明新）。

### C. 版本不符（写 A 装 B）—— **这是本轮唯一的真缺陷**

| 文件 | 行 | 声明 | 实际 | 差 |
|---|---|---|---|---|
| `requirements-dev.txt` | 10 | `pytest==9.1.1` | **9.2.0** | 次版本前进 |
| `requirements-dev.txt` | 12 | `ruff==0.16.9` | **0.17.3** | 次版本前进 |

**成因推测**：dev 清单的注释写着"版本为本地实测可跑的锁定值（最终回归 408 passed，2026-10-24 R-67 后）"，
而 408 那个数字早已涨到 730。说明**这两条锁定值是 10-24 之后就没再更新过的快照**，
期间环境被升级（很可能是我自己为跑测试装的），清单没跟着改。

⇒ 这正是"清单不等于事实"的标准样本：**锁定值成了历史化石，而它看起来还像约束。**
危险在于：新人 `pip install -r requirements-dev.txt` 会**降级**到 9.1.1，
然后在一个与当前 730 passed 不同的 pytest 上跑测试 —— 结果不可比，且会怀疑测试本身。

**建议修法（R53 自行取舍）**：把第 10 / 12 行改成实测值 `pytest==9.2.0` / `ruff==0.17.3`。
改完必须跑：全量 pytest（应 730 passed / 32 skipped）+ 变异（应 56/56、SKIP 0）+ `ruff check` 一把。
若 `ruff 0.17.3` 与仓库 `ruff.toml` 有新增规则导致 lint 红，**不要顺便改代码**，
把 lint 结果写进记录交人工（那是另一件事）。

## 3. 无版本锁定的依赖

**主清单 0 条**、**dev 清单 0 条** —— 全部是 `==`。这一点做得比多数项目好。

⚠️ 但 `uvicorn[standard]==0.52.4` 的 extras 会带进一组**未锁定**的子依赖
（`httptools` / `uvloop` / `websockets` / `watchfiles` / `python-dotenv` 等）。
它们不在任何清单里、版本由 pip 当时的最新决定 ⇒ 换时间重装会得到不同结果。
这属于"extras 的固有缝隙"，**修法是另建 lock 文件，不是往 requirements 里逐条抄**——留给人工。

## 4. 一个附带发现：`import audit_conflicts` / `coverage_probe` 靠 sys.path 硬插

AST 扫描把这两个判成 ORPHAN，追下去发现：

```python
# tests/test_audit_auto_schedule.py:18
sys.path.insert(0, os.path.join(os.path.dirname(__file__), "..", "..", "scripts"))
import audit_conflicts as ac

# tests/test_apply_match.py:451（函数体内）
sys.path.insert(0, os.path.join(os.path.dirname(__file__), "..", "..", "scripts"))
from coverage_probe import _key
```

两个被测模块的真实位置是 **`work-repo/scripts/`**（仓库根，不在 backend/ 里）。

⇒ 这解释了 `_iso_prep.sh` 为什么必须拷 `scripts/` 那一项：
**缺了它，这两个测试文件会 ImportError**，也就是记录里说的"缺后两项会静默少跑 20 个用例"的机制来源。

⇒ 顺带回答了一个旧疑点：`backend/tests/conftest.py:28` 只插入了 `backend/`，
**不含 `scripts/`**；所以这两个测试各自硬插了 `../../scripts`。
这是测试内的局部约定，脆弱但有效，**R53 不要动它**。
