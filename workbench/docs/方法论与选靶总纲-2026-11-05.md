## 找 bug 的方法
- **双轨**：①差异/往返预言机 fuzz 证明核心没坏；②扫带复现的 open bug（真正产出 PR 的轨道）。成熟库纯随机 fuzz 几乎必是干净负结果——价值在**证明清白**，不是拿来开 PR。有效 oracle：往返一致性（行式格式最好）、差分预言机、不变式单调性、字段边界、端到端 CLI。
- 优先「**读源码做安全/正确性审计 + 有真实用户影响的 bug**」，而非「扫 issue」：3 个 merged 与 ludic #151 全来自源码审计；所有扫 issue 尝试都撞红海（tinycss2 `url(\1)` 是真 bug 但属无真实场景的边角、PR #79 被拒；`serialize_nth` 169/169 干净负结果）。
- **先跑作者留的 `__main__` 自测**：日志第一行自相矛盾往往就是 bug（marl-ecdsa failover 的「Normal consensus」轮立刻打 `View change: primary_timeout`），比读代码快。
- **判重三连**（已自动化，见工具链）：issue 列表 + open PR + **closed PR / issue timeline**；三条件=同文件+同函数+同语义，必须 diff 补丁、看标题会误判。croniter #287 因未扫到 #281 白开；babel 5 个漂亮 issue 每个都挂着 open PR；Box 证明「open PR 少」≠「没人做过」。

## 高命中漏洞模式（源码审计清单）
- ★ **验签类必问**：函数有没有校验「被签的字节」与「调用方声称的载荷」是同一个东西？marl-ecdsa `verify_action_package` 只验自带 `message_hex`、不看 `agent_id/action/timestamp/nonce` → 复用**公开历史签名**即可伪造任意交易（`597cabe`）。签名重放/授权混淆不需伪造签名。哈希链若 `block_hash` 本身无签名，重算哈希就能过；修复要从明文重建 action 走验签，`extra` 等未签字段仍是残留面。
- ★ **兄弟实现必查同步**：同一接口两个实现时（`factory` 的 `if mode==`、`standard_*` vs 主实现），上次安全修复通常只改一个。marl-ecdsa 等权基线漏了 CW-PBFT 的女巫门控 → 伪造 `voter_id` 凑够 Quorum（`4760fa9`）。对照组最易被忽略，却是结论基石。
- ★ **跨仓同源代码的修复不会自动传播**：`verify_action_package` 在 marl-ecdsa `597cabe` 修了载荷绑定，复制进 AeroRider 的 `ecdsa_utils.py` 仍是修前版 → 11-04 复现「篡改业务字段 + 重算无签名 `block_hash` 后 `verify_chain` 全绿」并修复（`eb74b0a`）。**先拿已修过的漏洞模式反查兄弟仓与复制文件**，命中率远高于从零扫。
- ★ **`get(k, 0)` 的 0 是最危险的哨兵值**：时间戳/计数器用 0 当「从未设置」，一旦参与 `now - x > timeout` 就成「永远超时」（marl-ecdsa failover 心跳，20 轮只注入 3 次拜占庭却报 20 次 failover，`7caa0d8`）。问法：「缺省」是「未知」还是「零」？是「未知」就不能参与数值比较。
- ★ **`max(lo, min(hi, x))` 不是 NaN-safe**：`min`/`max` 对 NaN 比较恒 False → NaN 保留在**上界**，marl-ecdsa 激励链路让「奖励算崩的智能体」拿满分（`8ba090c`）。钳位必须显式判 `math.isfinite`。**累加器/账本写入必须拒收非有限值**：`x += NaN` 后恒为 NaN，永久中毒且无报错，写入边界要 fail-closed。
- ★ **电报里的「自报 ID」永远不可信**：去重/防重放/缓存键若直接用报文自带 id（`msg_id`/`request_id`），攻击者填唯一值即可绕过（marl-ecdsa P2-13 `get_msg_id` 读自报值绕 `_seen_msg_ids`）。修复=从内容重算指纹。隐藏坑：`f"{Enum.X}"` 取 repr 但 JSON 编解码后变值 → 收发重算键不一致，必须枚举归一为值 + 加「线上 encode→decode」回归锁。
- ★ **强制质量门上的误报比漏报更糟**：兜底正则 `\b\d{8,}\b` 把正文任意 8+ 位数字当引用 → 卡掉合格指南（comment-distillery `verify_citations`）。修复=删裸长数字兜底，只留 `c\d{6,}`。**机验脚本对语料列有隐含契约**：`prep.load_records` 必须有 content 列，缺列会静默返回 0 记录（不是 bug，是语料构造错）。
- ★ **「按内容挑分隔符」的启发式永远不安全**：`f'{k}="{v}"' if '"' not in v else f"{k}='{v}'"` 遇到同时含 `"` 与 `'` 的值就击穿（ludic #151：`He said "it's fine"` 把 `title` 截断并多出垃圾属性；构造值可注入 `onmouseover`）。修复=固定分隔符 + 转义分隔符本身。**文本与属性是两个转义上下文**：`html.escape(s, quote=False)` 对文本正确，被引号包裹的属性值却因此可逃逸。找法：搜 `html.escape(` 看第二参数是否 False，再追结果拼进哪个上下文。
- ★ **假阳性规律（最重要）**：每次「发现 bug」先问「是不是我 oracle 写错了」（mahjong 三次、croniter 四次；11-04/11-05 累计又七次）。典型：①全文 grep 命中≠函数体内语义 → 判据必须落在**目标函数体内用 AST**；②`_payload_equivalent`（`json.loads(a)==json.loads(b)` 字典相等、只放宽数值写法）不是放行旁路；③`".value" in seg` 找 `getattr(mt,"value",mt)` 恒 False → 字符串判据要用 AST 结构；④守卫函数**体内**的 `max(low,min(high,v))` 是 `isfinite` 之后的合法钳位，不算残留；⑤文档里的 `ghp_`/`AKIA` 前缀命中是说明文字，不是凭据泄露。**判据必须区分「前缀字符串」与「真实形态 token」**。
- **跨仓扫描三类非风险命中**：①`scan_out`/`*-main/` 只读快照里的缺陷版**是预期**（保留修复前状态，R110/R111）；②带 `.git` 的活跃目录可能过期；③只有先 GET 远端原文核验后，本地命中才算真漏洞。**「修复未传播」的判定对象必须是远端真源，不是本地副本。**

## 选靶与政策
- **红海**：纯 Python 热门库小修窗口被 agent 洪流淹没（tabulate 30+、tomlkit 33、xmltodict 15、validators 25+）；剩余真 bug 多在拥挤脆弱子系统或需设计决策（jsonpickle #454、reader #305）。策略：换低拥挤小众库或做实质 feature/复杂修复。
- ★ **选靶三信号缺一不可**：openPR 低 + 明确接受外部 PR + 纯逻辑可离线复现。**低 open-PR 数只是「值得去读政策」的提示，不是机会**：三种成因=①拒绝外部贡献（openai-agents-python 8 PR、`python-socketio` 0 PR 明写拒 unsolicited PR）；②维护者合并极快（`cdgriffith/Box` 7 个 issue timeline 都挂已 closed 修复 PR、汇总 #346）；③主动清理 agent 边角 PR（`Kozea/tinycss2` #77/#79/#81/#82 全 `closed,merged=False`）。**反例**：`getludic/ludic`（0 PR、★895、CONTRIBUTING 明确欢迎、无重依赖、当日活跃）→ 11-04 开出 #151。**决定性变量是 CONTRIBUTING 原文，不是 PR 数**。
- ★ **政策要读全文、多路径**：CourtBouillon（tinycss2/WeasyPrint）要求「Report real bugs you have in real life」「Ask before sending code」「一次只能一个 PR」「Use your own words」，maintainer 原话 *"hard to talk to bots all the day long"*。政策文件不止 `CONTRIBUTING.md`：`lemon24/reader` 在 **`CONTRIBUTING.rst`**（383 行），只查 `.md` 会整个漏掉。必须覆盖 `.md` / `.github/` / `.rst` / `docs/` / 无扩展名。其他门槛：python-sdk 需先被指派 issue；graphiti 要 rfc-approved + AI 披露 + 14 天关闭；ruyi 需 DCO sign-off。
- ★ **AI 贡献禁令是比拥挤度更前置的硬门槛**，必须**在选靶阶段一票否决**（`scout_targets.py` 判 `AI_BAN→EXCLUDE`）；事后合规复核只能「提前知道」不能「挽回」。
- ★ **第四类假靶：maintainer 只接受特定类型修复**（`tkem/cachetools` 三信号全绿，但关 #425「NaN 输入校验」原话 *"I don't think we should explicitly guard against each and every potential input-error"*，而 #440「插入失败留下不可用条目」回 "Nice catch… Fixed and merged" → 拒「用户输入错误」类、收「库自身状态损坏」类）。**选靶必须读 PR/issue 的关闭评论判断 maintainer 口味**。
- ★ **全局排序搜索已被批量生成内容污染**：`search/repositories` 按 pushed、`search/issues` 按 created 会返回大量模板仓（几百 star 却有 #148895 的 issue），命中 8333/21355 但信噪比极低 → 不能靠全局排序，须从可信库清单 + 结构化 `/repos/X/issues?labels=bug` 出发。这是 agent 洪流在搜索层的新形态。
