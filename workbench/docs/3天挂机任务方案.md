# 3 天挂机任务方案（已按真实环境校准）

> 模式：**自动修复并推送**（你选的）
> 已实测验证：本机 `git push` 不可用，但 **Git Data API 可完成等价推送**（见第三章）

---

## 一、我实测出的三件事（这决定了方案能不能跑）

| 测试 | 结果 |
|---|---|
| `git clone https://github.com/...` | ❌ `Connection was reset` |
| `git ls-remote` | ❌ `Could not connect to server` (443) |
| `curl https://github.com` | ❌ HTTP 000（20s 超时） |
| `curl https://api.github.com` | ✅ HTTP 200 (0.27s) |
| `curl https://codeload.github.com` | ✅ HTTP 301 (0.62s) |
| `raw.githubusercontent.com` | ⚠️ HTTP 301 但 16s |

**结论：git 协议走不通，API 完全可用。**

如果按常规思路写"每轮 git clone → 改 → git commit → git push"，**第一天第一轮就会卡死**。

## 二、解决方案：`gh_push.py`

用 Git Data API 实现等价推送，已写好并**真实跑通**：

```
base: 8f080386a9  tree: ffc4245d8e
  blob smoke/docs/ortools-compat.md -> b663db6b73
tree: 4ca9462961
commit: 493504e2fc

✅ 已推送 -> main @ 493504e2fc
```

远端验证：`main` HEAD = `493504e2fc`，文件 3719B → 4103B，新段落已生效，未误建目录。

### 它的工作方式

```
GET   /git/ref/heads/main        取 base commit
GET   /git/commits/{sha}         取 base tree
POST  /git/blobs                 每个改动文件 → blob
POST  /git/trees                 base_tree + 改动 → 新 tree
POST  /git/commits               tree + message + parent → commit
PATCH /git/refs/heads/main       更新 ref  ← 这一步才真正"推送"
```

### 用法

```bash
# 试运行（只建 blob/tree，不留痕）
python gh_push.py --repo TrueFurina/physics-scheduler-agent \
  --message "test: xxx" --file backend/app/foo.py --strip-prefix work-repo --dry-run

# 真推送
python gh_push.py --repo TrueFurina/physics-scheduler-agent \
  --message "fix(x): ..." \
  --file work-repo/backend/app/foo.py \
  --file work-repo/backend/tests/test_api_auth.py \
  --strip-prefix work-repo
```

### 安全设计

- **不加 force**：`"force": false`，若远端 ref 在读取后被改动，PATCH 会失败而不是覆盖
- **`--dry-run` 只读到 tree**，不在仓库留任何东西
- **`--strip-prefix`**：避免把本地路径前缀提交进去（实测踩过：不加会把 `smoke/docs/x.md` 建成仓库根的 `smoke/docs/x.md`）

## 七、三个必须知道的前提

### 1. 我不是常驻进程

我一次一问。要真无人值守，需要你的客户端支持定时任务，按第六章时间表配置。

### 2. `work-repo` 不是 git 仓库

codeload 解包出来的目录没有 `.git`。所以：

- 不能 `git diff` 看改了什么 → 用 `gh_push.py --dry-run` 确认改动文件
- 不能 `git log` → 历史在 `ROUND_LOG.md` 里
- 推送靠 `gh_push.py`，不靠 `git push`

### 3. 配额共享

5000/小时，每轮 200–500 次（blob 创建也要配额）。与其他会话共用，注意不要在同时跑别的重活。

## 九、一句话总结

**这个方案能跑，是因为我先把"git push 走不通"这件事测出来了。**

如果没测，方案会在第一轮卡在 `git clone` 上，而你可能要过几个小时才发现。

真正决定成败的不是"跑 3 天"，是**每一轮都能停、留痕、可回滚**——所以护栏第一条是：**不许改已有测试的断言**。
