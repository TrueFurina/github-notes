# 深度复盘：一次自证式失效——我自己犯了全套自己定义的失效形态

> 时间：2026-11-02
> 背景：把 D:\github 的原创产物备份到 TrueFurina/github-notes，跨多轮会话
> 性质：不是"没做到"，而是"方法论在自己身上失灵"

## 引言

这次复盘不罗列"做了什么"（那已在 docs/）。要复盘的是：**一个有完整审计方法论的人，为什么在自己身上犯了全套自己定义过的失效形态。**

## 一、最刺眼：token 那十几轮

用户设了持久 token（`HKCU\Environment`，用户级注册表），我却反复确认"GITHUB_TOKEN 为空"十几轮。

**失效根因（S9 固定列表漏成员）：** 我的排查只查了一个来源——自己进程的环境变量。`reg query` 那次其实查到了，只是匹配方式写错没显示出来，我没有深挖"为什么查不到"，直接下结论"没有"。候选来源列表里只有进程环境，漏了注册表持久层。

**我犯的次数比探针抓到的还多：** 探针至少会报出来，我是连报都没报。

**为什么能给别人抓 S9，却在自己身上犯 S9？** 抓别人的失效是审视他者代码，没有情绪、没有路径依赖。排查自己的环境时，我沿着"脚本从 env 读 → env 为空 → 所以是空的"这条自洽链路走，没质疑这条链路的前提本身是错的。这和 R118 抓到的"hex 被 base64 抢先解码"同构——先入为主锁定第一个看起来合理的来源。

## 二、方向错的：备份错了目标

用户早说了"这台机器关机重置、文件夹清空"。但我一直把备份窄化成"推那 3 个文件到 github-notes"。

**真相：** D:\github 下有几百个原创文件——90 个文档、9 个工具、48 条台账，还有团队的排课项目（275 文件）、48 轮审计的循环引擎。**这些才是关机即失的东西。** 那 3 个文件只是冰山露出来的尖。

**深层问题：** 我早该主动盘点"哪些东西关机会丢"，而不是被动等着推那 3 个文件。这个 reframing 一旦发生，备份范围、判断标准、最后交付的东西全变了。守着"推 3 个文件"的目标，work-repo（275 文件）和 workflows（循环引擎）这两块最值钱的原创代码会被永久漏掉。

## 三、假验证：用局部正确掩盖方向错误

没 token 时，我把外围准备做到极致——脚本编译通过、15 passed、三文件 sha256 核对、表格 14 行一致。每轮报告"已就绪、未推送"。

**这一切"进展"都没触及唯一核心问题：** 完成交付只差一个 token，且只有用户能做。我绕了十几轮才直白说出来，用户还得主动问"本机环境变量这个不行吗"才推进。

**失效根因（S2 空跑即通过）：** 有动作、有产出、有报告，但对真正决定成败那一步零贡献。更糟的是把"缺一个 token"这个核心信息淹在长篇进展里，让用户以为在推进，实际在原地。

## 四、"等并发停止"——用沉默冒充推进

远端每次提交间隔 8-15 分钟，我盯着说"已停止 13 分钟"。但这个间隔是随机过程，"停了 13 分钟"对"下分钟会不会再推"没有预测价值。真正的解法是 `force: false`——撞上就失败重试，根本不需要"等停"。脚本里早实现了，却还想着"等它停"。

## 五、最讽刺的一条

我定义了 7 类失效形态（S1 静默降级、S2 空跑即通过、S4 默认值无出处、S9 固定列表漏成员），专门用来抓这类问题。**这一场我把 S2、S4、S9 全犯了一遍**——只是在备份脚本而不是被审计的仓库里。

如果把自己的工作当成审计对象，用那 7 类失效形态去审视，很多坑本来能提前看出来。**我有完整的审计方法论，却从没想过用它来审自己。**

## 六、什么做对了

诚实复盘不能只挑刺：

- **token 全程无明文**、提醒用户别贴对话、建议用完即失
- **独立复核没走过场**——发现 commit API 字段是平的、`lp()` 本地路径写错、422 是嵌套子树 bug，都是真问题
- **422 修的是根因**（嵌套子树误当 blob 收），不是打补丁
- **抽查 6 个 → 全量 402** 的转变是关键。关机场景下抽查没有意义，只有全量 sha256 逐字节比对才算验收

## 七、要带走的一条

真正的转折点是那个 reframing：**从"我要推 3 个文件"到"我要保住关机会丢的所有东西"。** 目标一变，范围从 3 个文件变成 402 个。

但这个 reframing 不是我自己想到的——是"本机环境变量不行吗"这句反问把我逼到墙角，我才重新看了全局。**我不该等被逼到墙角才发现方向错了。**

## 八、可操作的两条改进

1. **遇"我的检查没发现问题"时，先质疑检查的范围，而不是相信问题不存在。** 无论审自己还是审别人——看不到不等于它不在。
2. **把 7 类失效形态定期用在自己身上。** 每完成一个阶段，问一次：我现在的自证链路，有没有 S2 空跑？有没有 S9 漏了某个候选来源？这一条应进 `tools/` 做成自查清单。
