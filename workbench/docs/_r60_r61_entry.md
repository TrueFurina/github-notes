## R61 · 2026-10-31 · `npm test` 绿了，可能只是少跑了几个文件

### 发现的经过

R59 台账里我写过一句"前端测试计数不太稳（126/130/135）"，当时怀疑是自己的
`grep` 被 ANSI 颜色码干扰。两种解释都只对了一半：

1. **确实有颜色码干扰** —— 不加 `NO_COLOR=1` 时，`grep "^ ✓ src"` 会漏行；
2. **但也确实在掉文件** —— 关掉颜色连跑三次：

```
17 files / 137 tests     ← 全了
16 files / 128 tests
16 files / 132 tests     ← 都报 "16 passed"，退出码都是 0
```

再连跑两次抓住实证：某一次 `src/views/__tests__/views.test.tsx`（36 条，最大的一个文件）
**整份没出现在运行列表里**，而汇总是 `16 passed / 0 failed`。

也就是说：**`npm test` 通过，不代表测试都跑了。** 这一晚我据此写过两次"全绿"，
其中至少一次少了 36 条。

### 根因（不在本项目代码里）

日志里伴随一条 `node-brokered-fs-shim.cjs` 的内部错误 —— 宿主运行环境的写盘垫片。
worker 中途消失，掉队文件既不报错也不计入失败。试过 `--pool=forks`：更糟
（14 files / 85 tests），所以不从 pool 侧修。

### 改法：把"少跑了"变成红色

新增 `scripts/vitest-guarded.mjs`，接到 `npm test` 上（原行为保留为 `npm run test:raw`）：

1. 用 `--reporter=json --outputFile` 拿**真实**计数；
2. 判据是"不少于已知基线"（17 files / 137 tests）—— 用 `>=`，**新增测试永远不会误报**，
   只有掉队才会红；
3. 偶发掉队**自动重试一次**：只有连续两次都不完整才算失败。
   把环境抖动变成日常红灯，红灯见多了真问题也会被忽略；
4. 0 条失败但 vitest 自身报错退出（本机实测过：fs shim 报 "Errors 1 error"）
   也判失败 —— 报告不完整的一轮，绿说明不了什么。

一个坑记一下：JSON 里 `numTotalTestSuites` 数的是 **describe 块**（本仓库 48），
文件数是 `testResults.length`（17）。两个数字差得远，第一版守卫就是拿错了字段，
报出"✅ 50 files"。

### 验证

```
第 1 次不完整：只跑了 16 files / 101 tests，重试一次…
      Tests  137 passed (137)
[vitest-guarded] ✅ 17 files / 137 tests（基线 17/137，第 2 次尝试）
```

真实抓住了一次掉队并自动重试成功 —— 这正是它要处理的情形。

### 提交

`80ae9ec9c3`（父 `38fdf51af0`）—— 2 个文件，`package.json` 两行 + 守卫脚本 105 行。

### 教训

**"测试通过"这句话，得先确认测试真的跑了。**

这一晚我三次写下"N passed / 0 failed"，其中两次的数字是少跑出来的。而我当时
甚至有理由相信它 —— 因为我看到的每一行都是绿的。

判据要写在能被机器检查的地方：**数字低于基线就红**，而不是"我觉得这次应该跑全了"。
