## 一·补：`.gitignore` 的局限（自查发现）

上一轮我加了 `.gitignore` 规则，但**忽略了它在 Git 中的一个关键特性**：

> `.gitignore` 只对**未跟踪**的文件生效。已跟踪的文件加入 `.gitignore` 后，**仍会正常提交、仍可公开访问**。

实测确认（加了规则之后）：

```
MangDeZhiXun/.env                    HTTP 200  ← 仍公开可读

MARS-408/py-server/iq_run_tmp/.env.test  HTTP 200  ← 仍公开可读
```

所以上一轮那 4 个提交**只防新增，不防已有**。表述为"消除风险"是不准确的，准确说法是"阻止风险扩大"。

**补做的处置**：

- `MARS-408` 的 `.env.test` 属于测试弱口令（非真实凭据），且 `iq_run_tmp` 无任何代码引用（代码搜索命中 0），可安全删除 → **已执行**：删除原文件 + 建 `.env.test.example` 模板（值全空）

**关于"为什么不删 `.env`"的说明**：

这是最容易做错的一步。直觉是"删掉就安全了"，但实际是：

1. `git rm` 会产生一个新提交，内容 diff 里包含被删文件的完整内容
2. 原文件在历史的旧提交中依然存在、依然可访问
3. 真正的解法是"先让密钥失效，再考虑清理"

**当前正确的状态**：`.env` 仍在仓库，但 `.gitignore` 已阻止新的 `.env` 提交。等密钥轮换完成后，再决定是否移除文件本身。
