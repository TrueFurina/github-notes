## 二、两种新失效形态（补 S1–S7）

### S8 链路级死胡同

> **每一个环节都正确、724 条单测全绿，但连起来用户走不通。**

**真实案例（R50 端到端冒烟·断点①）**

```
/parallel/solve 默认参数：45 个单元 / 固定周日 / 每周 4 格 → 需 12 周
但可用窗口只有 11 周  → 报错「排不下，请把起始周调早」
```

后端把**原因**和**两条出路**（调起始周 / 减项目组别）都写得清清楚楚，前端也忠实显示了红字——**每个环节都对**。但：

- `client.ts:298` 只传 `class_name + weekday`，**从不传 `start_week`** → "调起始周"这条路前端**没有入口**；
- "减项目/组别"同样无入口；
- 唯一能走的 workaround 在**另一个界面**（主数据→班级→起始周），而报错文案**没指路**。

而 `/parallel/solve-all` 同一个班 `scheduled=45`、全校 17/17 排满——**两个入口给出相反结论**。

**判据**：错误文案里承诺的"出路"，在客户端是否有**可达入口**。

**与 S1–S7 的区别**：前七种都是**单点**缺陷（某个函数、某个守卫、某个默认值）；S8 是**组合**缺陷——单测覆盖"函数对不对"，不覆盖"报错之后用户有没有路可走"。

### S9 判据自身腐烂

> **守卫曾经有效，随被测代码演进，判据锚点失配，从此永远 SKIP，却仍打印"全检出"。**

**真实案例**

`mutation_check.py` 的 **M30**：那段 `return` 后来多了 `ai_plans_source` 字段，变异体的锚点整段**失配** → 从此长期**静默 SKIP**；而脚本退出码**不看 SKIP**、只看"检出数"→ 一直报"全检出"。

在 R49 之前，没有任何一轮发现它——因为它伪装成的正是"通过"。

**判据**：
1. 变异检出的 **SKIP 数不为 0** 时，逐条问"为什么 SKIP"；
2. **SKIP 必须进退出码**，否则"被跳过"会被读成"通过"。

**与 S3（守卫空转）的区别**：S3 是**从未有效过**；S9 是**曾经有效、后来腐烂**。后者更隐蔽——因为历史记录里它一直是绿的，没人会去重新怀疑一个"一直通过"的守卫。**失明的绿灯比红灯更危险。**

### 附：一个元认知陷阱（自设约束冒充硬约束）

> **把"某人写下的阈值"当成"物理限制"，并据此做出错误决策。**

**案例**：`ROUND_LOG` 的 `12000 行上限`，是守卫自己设的，**不是文件系统限制**。把它当硬约束，就会推出"到顶只能停止重贴、情报通道失效"的错误结论——而真实解法（调高阈值，或改成"指针式贴法"）根本不受这个数限制。

**判据**：遇到任何"上限 / 配额 / 阈值 / 硬约束"，先问一句：
**这是物理的，还是某人写的？**

> 同类还有：GitHub 的 `core.remaining < 200 就只做分析`、`改动 ≤ 3 文件`——都是策略，不是物理。

## 四、固化下来的机制（不是感想，是下次能直接执行的）

| 机制 | 内容 | 起因 |
|---|---|---|
| **推送通道** | bash 沙箱 git 协议被封 → 走 `D:/github/gh_push.ps1`（Git Data API，token 取 **User 作用域**），先 `-DryRun` 核 blob 路径再真推 | `git push` 502 |
| **核验反射** | 任何"已完成/已还原/已修复"自述，配一个可证伪动作：`diff` / `md5` / API 回读远端 HEAD | R47 / RSA |
| **差数判据** | 差数出现，先查"内存侧有没有这个维度的取数入口"（口径），再查数据 | 16 vs 0 |
| **兄弟提交认知** | API 推送后本地 `git status` 仍 `ahead>0` 是假象（同父兄弟提交），内容已在 origin，需 API 核验 HEAD 确认 | Git Data API |
| **并发识别** | 看到**非本会话所做的**脏文件（本轮 `ctf_agent` 冒出 25 个）→ **一律不提交**，避免覆盖并发 worker | R58 事故同族 |

## 五、诚实的局限

1. **跨会话无记忆**：这些教训如果不落成文字，下一个会话的我会原样再犯"缺依赖当逻辑 bug"。所以本文与每轮的 `本轮教训` 段落才是真正的"留存"，其余只是上下文里的临时清醒。
2. **并发不可控**：本轮 `audit-xihu-git/ctf_agent` 出现 25 个非我所做的改动（14 改 + 11 新测试），来自另一个 worker。能做的是**不碰**，不能做的是"帮它收口"。
3. **报缺陷 ≠ 修缺陷**：R50 报了 4 条断点，因本轮允许 0 改动，全部**只记录未修**。**一条被报告却无人处理的缺陷，等于没报。**
4. **体积在逼近上限**：`ROUND_LOG` 10806 行，「常备操作情报」被重贴 **19 次**，末段守卫重贴占 **23%**。体积杀手是重复，不是内容。

## 七、如果只记三句

1. **"验证通过"不等于"问题解决"**——要问这个验证本身能不能被骗过（S9：失明的绿灯）。
2. **差数先疑口径，绿灯先问"为什么绿"**——最贵的三次推翻，两次都发生在"我准备下结论"的前一秒。
3. **自我报告必须独立核验；但过度怀疑、把真相当误报，也是误判**——怀疑要有动作，不能只凭姿态。
