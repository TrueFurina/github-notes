这是这轮最重要的一句话：

`grep -r "_docker_keepalive" .` 会命中 **5 处**，其中 2 处在缓存里、是坏的、

## 四、过程中的三次误判（都在分类规则上）

### 误判 1：把只读快照当成活跃目录

第一次跑出结果：

```
❌ **活跃** audit-xihu/xihu-sword-ctf-agent-main/…/_verify_failopen.py
```

我以为是漏同步了。核对后才发现：C（`audit-xihu/...`）是 tarball 快照，
**它本来就该保留修复前的样子**——R110 就是靠它证明"这些修复确实是后来才有的"。

**修 C 会毁掉它的证据价值。**

### 误判 2：只按顶层目录名分类

加了「只读快照」规则后，`audit-xihu` 仍被归入"审计主副本"。原因：
我按顶层名 `audit-xihu` 分类，而快照在它的**子目录**里。

改成"看实际含代码的最深一层"，才对。

### 误判 3：取 sample 路径时写反了嵌套

```python
sample = next(iter(files.values()), [[]])
sample_path = sample[0][0] if sample and sample[0] else full   # ← 错
```

`files` 是 `{文件名: [路径...]}`，`next(iter(...))` 得到的是**路径列表**，
不是嵌套列表。正确写法：

```python
first_list = next(iter(files.values()), [])
sample_path = first_list[0] if first_list else full
```

结果 `sample` 一直是 `"D"`（盘符），规则永远不生效。

**三次误判都在"分类"这一个动作上。** 而分类错了，后面所有结论都是错的——
第一次跑出"2 处在活跃目录"，如果不去核实，就会去改只读快照。

## 五、交付：`tools/workspace_map.py`

| 判据 | 内容 |
|---|---|
| **W1** | 每个含代码目录：规模 + 类别（按**实际含代码的最深一层**判定） |
| **W2** | 已知缺陷标记的**分布**（修复版 vs 缺陷版，各在哪个目录） |
| **W3** | 风险判定：缺陷版是否位于**活跃目录** |

活跃 = 会被 import、会被改的目录（审计主副本 / 工作副本 / 其他）。
只读快照与缓存里的缺陷版只标 💤，不算失败——但**而是照实列出来**。

### 自检（3 项）

```
[PASS] T1 缓存目录被正确分类
[PASS] T2 审计副本被正确分类（这是活跃目录）
[PASS] T3 修复版被正确识别
```

## 六、这一轮真正的发现

能做的是：**让它每次都能被打印出来**——包括那些我以为不重要的缓存。

## 八、三条可复用的

1. **"不会影响运行"和"不会造成误导"是两回事。**
   缓存里的缺陷代码不会被 import，但会被 grep 到、被当成参考。

2. **分类规则错了，后面全错。**
   这轮三次误判都在分类上。第一次跑出"2 处在活跃目录"时，
   如果直接去改，我会毁掉只读快照的证据价值。

3. **只读快照要标出来，但别改它。**
   它的价值在于"保留修复前的样子"。R110 靠它证明了修复是后来才有的；
   如果把它同步了，下次就再也证明不了。
