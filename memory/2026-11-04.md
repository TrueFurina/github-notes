## 环境事实修正：git 代理 502 的真正解法是 HTTP/1.1，不是「多试几次」

- 11-04 二次 memory 推送时 `git push origin main` 连撞 3 次 `CONNECT tunnel failed, response 502`，`git fetch` 连败 5 次（含 `Empty reply from server`）。本日日志第 14 行「重试即可恢复」的判断不完整。
- 实测解法：`git -c http.version=HTTP/1.1 fetch origin` **一次成功**（`7f2a0ad..e310bcf`）；随后普通 fetch 也通。判断是代理对 HTTP/2 CONNECT 隧道处理有问题。
- 兜底链：① `-c http.version=HTTP/1.1` 加在 fetch/push 前；② 仍不通 → REST Contents API PUT（api.github.com 与 github.com 走不同路由，git 全挂时 API 正常）；③ API 推送后本地 `fetch` + `rebase origin/main`，git 自动 `dropping ... patch contents already upstream`（零丢失）→ 本地==远端。
- 本次完整走通 ③：本地 `a9217c4` 被判「patch contents already upstream」丢弃，HEAD 变 `e310bcf`，工作树干净、本地==远端、两份 memory 镜像 md5 一致。
