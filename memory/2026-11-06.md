### ★ easydict 真 bug（源码审计，无重复 PR）
- 全文件（逻辑仅 `__init__`/`__setattr__`/`update`/`pop` 数行）读完 + 跑基线 **60 doctest passed**，写定向探针。
- **根因**：`update(self, e=None, **f)` 里 `d = e or dict()`——当 `e` 是非空 dict（truthy）时 `d` 直接**别名** `e`，随后 `d.update(f)` 把关键字参数**写进了调用方的 `e`**。`obj.update(src, key=val)` 这种标准 `dict.update` 用法会静默改写调用方入参；而标准 `dict.update` 从不改入参。
- 复现：`src={'a':1}; d.update(src, b=2)` → `src` 变成 `{'a':1,'b':2}`（调用方被改）。
- **修复**（1 行）：`d = dict(e) if e else {}`（对入参做副本）。所有合法输入行为不变，仅消除「改写调用方入参」副作用。
- 回归测试：加 doctest 断言 `src == {'a':1}` 不变。整 doctest suite **64 passed**（原 60）。
- **判重三连复核**：2 个 open PR（#53 setdefault 属性、#51 禁用子类自动转换）均不碰此 bug；open issue #3 是「老版本 update/pop 不管属性」（当前 master 已修复、且未挂 fixing PR），与本次「改写调用方入参」是**不同** bug，在 PR body 注明区分。无重复 PR。

### ★ 真 bug：VariableMin/MaxSumConstraint 乘数估计写错（源码审计）
- 读全 `constraints.py`/`solvers.py`/`problem.py`/`domain.py`。两个类 `VariableMinSumConstraint`/`VariableMaxSumConstraint` 的 `__call__` 对**未赋值变量**用
  `sum_value += max(domains[var] * multiplier)`（MinSum）/ `min(domains[var] * multiplier)`（MaxSum）。
  `domains[var]` 是 `Domain`（`list` 子类）→ `Domain * multiplier` 是**列表重复**而非标量乘：
  - **float 乘数** → `TypeError: can't multiply sequence by non-int of type 'float'`，直接崩溃。
  - **整型乘数 ≠ 1** → `max([1,2]*2)=2`（应为 `max(1*2,2*2)=4`），**低估上界** → MinSum 提前剪枝 → **静默漏解**。
- 复现：a,b∈{1,2}, c∈{5}, `VariableMinSumConstraint('c',['a','b'],multipliers=[2,2,1])` → 期望 3 解，库返回 **0 解**（c 域最小被先赋值，触发未赋值路径）。float 乘数 → 两 solver 均崩溃。
- **修复**（2 行，最小、语义正确、兼容负乘数）：`max(value * multiplier for value in domains[var])` / `min(value * multiplier for value in domains[var])`。
- 回归测试：新增 `tests/test_constraint.py::test_variable_sum_constraints_with_multipliers`，对两类约束 × 4 组乘数（单位/整型/浮点/负）对拍暴力枚举。结果：CASE1 现 3 解、CASE2/3 float 不再崩且 0/9 解正确；probe2 浮点有解用例 8/9、整型 MaxSum 21 全对。
- **判重三连复核**：open PR 仅 #95（freethreading）、#53（LeastConflictsSolver），均不碰此 bug；唯一 open issue #102 不相关；`main` 当前仍带此 bug（未修）→ 无重复 PR。

### 新增可用教训
1. **`Domain` 是 `list` 子类 → `domain * scalar` 是列表重复不是标量乘**：凡在约束里对 `domains[var]` 做 `*` 都是隐藏 bug（崩溃或静默错），审计时 grep `domains[` 配 `*` 即可扫。与「`get(k,0)` 哨兵」「NaN-safe clamp」并列进清单。
2. **「未赋值变量估计用 `max/min`」路径是 CSP 库高命中面**：Variable*Sum 的 partial-estimate、forward-check 都在此处写反/写错；遇到带乘数的 partial 评估先盯这行。
3. **`Variable*` 类（约束到另一个变量）比普通约束更易踩顺序**：target 域更小会被先赋值，提前触发未赋值分支，放大 partial 估计 bug 的可见性——也是复现的关键。
