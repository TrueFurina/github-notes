## comment-distillery 审计 + 1 个真修复（用户：继续）
- 背景：marl-ecdsa 审计实质完成后，按「高价值 + 最终做完换项目」口径切到自有 AI 仓 comment-distillery。审计对象：强制质量门 `scripts/verify_citations.py`、数字机验 `scripts/verify_numbers.py`、逻辑层 `app/core.py`、蒸馏编排 `app/distill.py`。
- 结论：**两个机验脚本（核心逻辑）健壮**，仅在「兜底正则」上有 1 个高价值缺陷。
- 真缺陷：`verify_citations.DEFAULT_PATTERNS` 含裸 `\b\d{8,}\b`，把正文里**任意 8 位以上数字**（日期/时间戳 `20240901123000`/手机号/人数）当成引用去语料查，查不到就误报成「幻觉引用」——**强制质量门上的假阳性会卡掉本来合格的指南**。实测复现（`数据截止 20240901123000 共 4 条` → 该时间戳被判为幻觉）。
- 修复：删掉裸长数字兜底，只留 `DEFAULT_PATTERNS = [r"c\d{6,}"]`。理由：强制引用方式是结构化 `[源:ID]` 标记（方法论硬规则），纯数字 ID 写作 `[源:12345678]` 仍走主正则捕获，所以去裸兜底是安全的、且消除误报。新增 2 条回归：`test_long_numeric_non_id_not_flagged` + `test_pure_numeric_id_via_marker_still_checked`。
- 提交：`645d28e45f50691d403e72a4dc68c4dfdd04c640`（fast-forward 自有仓 main，非 force）。远端 Contents API 核验：DEFAULT_PATTERNS 已改、裸正则已删、docstring 已更新、两条测试已入。
