## 第五贡献：jmespath PR #391（已开，待评审）—— 印证「扫 issue + 小修」双管法
- 方法复用 croniter #280→#287 的路径：先差异预言机 fuzz 证明核心算术没坏（991 测试全绿、neg），再扫 open issue 命中 #381（带复现）。
- 缺陷：`floor()`/`ceil()` 把参数直传 `math.floor`/`math.ceil`，对 `Infinity`/`NaN` 抛**不可捕获**的 `OverflowError`/`ValueError`；而 `json.loads` 默认接受这两个字面量，正常加载的数据会带上它们。`abs/max/min/sum/avg` 都会透传非有限值（返回 float），唯独 floor/ceil 抛内置异常，破坏「坏参数→JMESPathTypeError」的一致性。
- 修法：`_func_floor`/`_func_ceil` 加 `if not math.isfinite(arg): raise JMESPathTypeError('floor'/'ceil', arg, 'non-finite number', ['number'])`。
- 验证：新增 `test_floor_ceil_reject_non_finite`（floor/ceil × Infinity/NaN 四个组合）、`test_floor_ceil_still_work_for_finite`。全量 `993 passed, 1 skipped`（基线 991 passed）。
- 工程细节：本环境 `github.com:443` 握手失败，git 推不上去。改用 **Git Database API**（blobs→tree(base_tree)→commit→ref→pulls，全程走 `api.github.com`）成功建分支、提交、开 PR。比 git push 更稳，记下来备用。
